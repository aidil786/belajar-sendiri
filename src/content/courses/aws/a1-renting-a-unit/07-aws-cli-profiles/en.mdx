<Card id="see-config" type="see">
A **<Term id="cli-profile">profile</Term>** is a named set of settings in `~/.aws/config`. Tap the line that picks the account.

<Interactive name="SpotLines" lines={[{ text: '[profile my-dev-profile]' }, { text: 'sso_session = my-sso' }, { text: 'sso_account_id = 123456789011', target: true }, { text: 'sso_role_name = readOnly' }, { text: 'region = us-west-2' }, { text: 'output = json' }, { text: '[sso-session my-sso]' }, { text: 'sso_region = us-east-1' }, { text: 'sso_start_url = https://my-sso-portal.awsapps.com/start' }]} prompt="Tap the account line." success="That number is the account. The role line says which badge to wear." />
</Card>

<Card id="see-login" type="see">
<Interactive name="Transcript" title="bash" label="aws sso login opens the browser, then says it logged into the start URL." lines={[{ cmd: 'aws sso login --profile my-dev-profile' }, { out: 'SSO authorization page has automatically been opened in your default browser.\nFollow the instructions in the browser to complete this authorization request.' }, { out: 'Successfully logged into Start URL: https://my-sso-portal.awsapps.com/start', color: 'green' }]} />

The browser asks you to approve, with MFA. The CLI then keeps short-lived badges in a cache. No key is saved in a file.
</Card>

Not using Identity Center? Since AWS CLI 2.32.0, `aws login` uses your console sign-in instead. It refreshes short-lived badges for up to 12 hours. No access keys needed.
