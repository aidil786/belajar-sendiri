<Card id="hook" type="hook">
Kedai Kancil’s web server must read the menu bucket. How should the server get its key?

<Interactive name="Choice" options={[{ label: 'Give the server a role to borrow', correct: true, why: 'It gets short-lived keys that renew by themselves. Nothing to steal from disk.' }, { label: 'Paste an access key into a file on the server', why: 'Anyone who copies the disk gets a key that never expires.' }, { label: 'Use the root user’s login', why: 'Never. Root stays locked away.' }]} />
</Card>

<Card id="see-how" type="see">
A role for a service is a **<Term id="service-role">service role</Term>**. Put the steps in order.

<Interactive name="OrderList" items={['Make a role the EC2 service may borrow', 'Give the role a small permissions policy', 'Attach the role to the server', 'The app asks the server for short-lived keys', 'The keys renew by themselves']} label="First step at the top" success="No key on disk. The server borrows, and returns." />
</Card>

<Card id="see-sort" type="see">
Every role has two notes. The <Term id="trust-policy">trust policy</Term> says who may borrow it. The permissions policy says what it opens. Sort them.

<Interactive name="SortCards" buckets={[{ id: 'trust', label: 'Trust policy (who may borrow)' }, { id: 'perms', label: 'Permissions policy (what it opens)' }]} items={[{ label: 'Principal: the EC2 service', bucket: 'trust', why: 'EC2 may borrow this badge.' }, { label: 'Action: sts:AssumeRole', bucket: 'trust', why: 'Borrowing a role is the AssumeRole action.' }, { label: 'Action: s3:GetObject', bucket: 'perms', why: 'What the badge lets the server do.' }, { label: 'Resource: the kedai-menu bucket', bucket: 'perms', why: 'Where the badge works.' }]} success="Who may borrow, and what it opens. Two notes, one role." />
</Card>

<Card id="win" type="win">
You can now give a server a role instead of a stored key.
</Card>

<Card id="deeper" type="deeper">
On EC2, the role rides in an "instance profile". Most AWS SDKs and the CLI find the role’s keys by themselves. Some services make their own service-linked roles.

Real rep: only with a budget alarm set. Make a role, attach a policy, then list it. Delete both when done (`aws iam detach-role-policy`, then `aws iam delete-role`).
</Card>
