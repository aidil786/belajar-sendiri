<Card id="see-sort" type="see">
That fence is a **<Term id="permissions-boundary">permissions boundary</Term>**: the most one user or role may ever do. An <Term id="scp">SCP</Term> is a fence around whole accounts. Sort the facts.

<Interactive name="SortCards" buckets={[{ id: 'boundary', label: 'Permissions boundary' }, { id: 'scp', label: 'SCP' }]} items={[{ label: 'Fence around one user or role', bucket: 'boundary', why: 'Set on the person or robot itself.' }, { label: 'Fence around whole accounts', bucket: 'scp', why: 'Set in AWS Organizations, on accounts or groups of them.' }, { label: 'Needs AWS Organizations', bucket: 'scp', why: 'No organization, no SCPs.' }, { label: 'Does not limit the management account', bucket: 'scp', why: 'SCPs skip the organization’s top account.' }, { label: 'Lets a team lead make roles safely', bucket: 'boundary', why: 'New roles must stay inside the fence.' }]} success="One fence per keyholder, one fence per account." />
</Card>

<Card id="try-swipe" type="try">
Fences limit. Keys open. True, or needs work?

<Interactive name="SwipeJudge" prose cards={[{ text: 'A boundary alone lets a role read S3.', good: false, why: 'A fence opens nothing. The role still needs an Allow.' }, { text: 'An SCP can stop admins in member accounts.', good: true, why: 'Even an admin cannot climb the account’s fence.' }, { text: 'An SCP limits the management account too.', good: false, why: 'SCPs never apply to the management account. Guard it well.' }, { text: 'A Deny in an SCP beats every Allow below it.', good: true, why: 'Deny wins, wherever it is written.' }]} />
</Card>

<Card id="predict" type="predict">
Your organization’s SCP allows `s3:*`. Aina has no IAM policy for S3. Can she read the menu bucket?

<Interactive name="Choice" options={[{ label: 'No: an SCP never grants anything', correct: true, why: 'It only says how far keys may go. Someone must still give her an Allow.' }, { label: 'Only in the management account', why: 'Keys come from IAM policies, in every account.' }]} />
</Card>

<Card id="check-region" type="check">
The shop’s accounts must stay in the Malaysia Region. An SCP at the root enforces it. Aina uploads to a bucket in `us-east-1`. Predict.

<Card id="win" type="win">
You can now tell keys from fences, and predict when a fence says no.
</Card>

<Card id="deeper" type="deeper">
Where the story breaks: a metal key opens its lock forever. AWS checks every request fresh, against every key and fence at once. And a robot can borrow a key for just minutes.

Real SCPs often exempt global services from a Region rule. Read the SCP examples in the Organizations guide before you write one.
</Card>
