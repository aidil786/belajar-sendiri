<Card id="see-sort" type="see">
Pagar itu ialah **<Term id="permissions-boundary">permissions boundary</Term>**: had paling tinggi untuk satu pengguna atau role. <Term id="scp">SCP</Term> pula pagar sekeliling seluruh akaun. Susun fakta ini.

<Interactive name="SortCards" buckets={[{ id: 'boundary', label: 'Permissions boundary' }, { id: 'scp', label: 'SCP' }]} items={[{ label: 'Pagar sekeliling satu pengguna atau role', bucket: 'boundary', why: 'Dipasang pada orang atau robot itu sendiri.' }, { label: 'Pagar sekeliling seluruh akaun', bucket: 'scp', why: 'Dipasang dalam AWS Organizations, pada akaun atau kumpulan akaun.' }, { label: 'Perlukan AWS Organizations', bucket: 'scp', why: 'Tiada organisasi, tiada SCP.' }, { label: 'Tak hadkan management account', bucket: 'scp', why: 'SCP langkau akaun teratas organisasi.' }, { label: 'Benarkan ketua pasukan buat role dengan selamat', bucket: 'boundary', why: 'Role baru mesti kekal dalam pagar.' }]} success="Satu pagar untuk setiap pemegang kunci, satu pagar untuk setiap akaun." />
</Card>

<Card id="win" type="win">
Kini anda boleh bezakan kunci dan pagar, dan ramal bila pagar kata tidak.
</Card>

<Card id="deeper" type="deeper">
Di mana cerita ini tak tepat: kunci besi buka mangganya selamanya. AWS semak setiap permintaan dari awal, terhadap semua kunci dan pagar serentak. Robot pula boleh pinjam kunci untuk beberapa minit sahaja.

SCP sebenar selalunya kecualikan servis global daripada peraturan Region. Baca contoh SCP dalam panduan Organizations sebelum menulisnya.
</Card>
