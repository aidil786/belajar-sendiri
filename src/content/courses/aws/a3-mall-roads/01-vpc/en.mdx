</Card>

<Card id="see-vpc" type="see">
A **<Term id="vpc">VPC</Term>** is your fenced plot in the mall. Your servers and databases live inside it. Some services live outside. Sort them.

<Interactive name="SortCards" buckets={[{ id: 'in', label: 'Inside your VPC' }, { id: 'out', label: 'Outside any VPC' }]} items={[{ label: 'Your web server (EC2)', bucket: 'in', why: 'Servers always live in a VPC.' }, { label: 'Your database (RDS)', bucket: 'in', why: 'It sits in your VPC, in a back room.' }, { label: 'An S3 bucket', bucket: 'out', why: 'S3 is a Region-wide storeroom. Buckets never sit inside a VPC.' }, { label: 'IAM users and roles', bucket: 'out', why: 'IAM is account-wide. It holds the keys, not the units.' }]} success="Sorted! Units live in your plot. The key office and the storeroom don't." />
</Card>

<Card id="see-cidr" type="see">
Your plot gets a block of addresses, written as a **<Term id="cidr">CIDR</Term>**. `10.0.0.0/16` has 65,536 addresses. A smaller number after the slash means a bigger block. Which is biggest?

<Interactive name="Choice" compact options={[{ label: '/16', correct: true, why: '/16 is the biggest block a VPC may have.' }, { label: '/24', why: '/24 holds 256 addresses. That is smaller.' }, { label: '/28', why: '/28 holds only 16. The smallest a VPC may have.' }]} />
</Card>

<Card id="try-plan" type="try">
This plot is far too big. Make the VPC a /16. Then give each wing one public row.

<Hint>Type `10.0.0.0/16` in the VPC box. Then pick a size for each row.</Hint>
</Card>
