<Card id="hook" type="hook">
Your workflow must push a new image to ECR and update the ECS service. It needs AWS keys. Which ones?

<Interactive name="Choice" options={[{ label: 'A short-lived role, borrowed with a GitHub badge', correct: true, why: 'Yes. OIDC from CI/CD World C3. Nothing is stored, so nothing old can leak.' }, { label: 'Access keys saved in repo secrets', why: 'They never expire. A leak works for years.' }, { label: 'The root user’s keys', why: 'Never. Root keys open the whole account.' }]} />
</Card>

<Card id="try-yaml" type="try">
Build the deploy workflow. No stored keys.

<Interactive name="YamlBuilder" workflow="Deploy to ECS" goal={{ order: ['push', 'perms', 'job', 'checkout', 'login', 'ecr', 'build', 'render', 'deploy'] }} blocks={[
  { id: 'push', kind: 'trigger', label: 'On push to main', yaml: 'push:\n  branches: [main]', means: 'Run when main gets new commits.' },
  { id: 'perms', kind: 'permissions', label: 'Ask for a badge, read the code', yaml: 'id-token: write\ncontents: read', means: 'The job may ask GitHub for an ID token.' },
  { id: 'job', kind: 'job', label: 'Job: deploy (production)', yaml: 'deploy:\n  runs-on: ubuntu-latest\n  environment: production', means: 'The trust policy checks this environment name.' },
  { id: 'checkout', kind: 'step', label: 'Check out code', yaml: '- uses: actions/checkout@v7', means: 'Copy the code onto the runner.' },
  { id: 'login', kind: 'step', label: 'Borrow the AWS role', yaml: '- uses: aws-actions/configure-aws-credentials@v6\n  with:\n    role-to-assume: arn:aws:iam::111122223333:role/kedai-deploy\n    aws-region: ap-southeast-5', means: 'Swap the badge for short-lived keys.' },
  { id: 'keys', kind: 'step', label: 'Log in with stored keys', yaml: '- uses: aws-actions/configure-aws-credentials@v6\n  with:\n    aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}\n    aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}\n    aws-region: ap-southeast-5', means: 'Keys kept in secrets.', why: 'Those are the long-lived keys we want gone.' },
  { id: 'ecr', kind: 'step', label: 'Log in to ECR', yaml: '- id: ecr\n  uses: aws-actions/amazon-ecr-login@v2', means: 'Docker may now push to your shelf.' },
  { id: 'build', kind: 'step', label: 'Build and push the image', yaml: '- run: docker build -t $REGISTRY/kedai-kancil:$GITHUB_SHA . && docker push $REGISTRY/kedai-kancil:$GITHUB_SHA\n  env:\n    REGISTRY: ${{ steps.ecr.outputs.registry }}', means: 'Tag it with the commit, then push.' },
  { id: 'render', kind: 'step', label: 'Write the new image on the card', yaml: '- id: render\n  uses: aws-actions/amazon-ecs-render-task-definition@c804dfbdd57f713b6c079302a4c01db7017a36fc\n  with:\n    task-definition: taskdef.json\n    container-name: web\n    image: ${{ steps.ecr.outputs.registry }}/kedai-kancil:${{ github.sha }}', means: 'A new recipe card with the new image.' },
  { id: 'deploy', kind: 'step', label: 'Roll out on ECS', yaml: '- uses: aws-actions/amazon-ecs-deploy-task-definition@df9643053eda01f169e64a0e60233aacca83799a\n  with:\n    task-definition: ${{ steps.render.outputs.task-definition }}\n    cluster: kedai\n    service: shop\n    wait-for-service-stability: true', means: 'Register the card, update the service, wait until healthy.' }]}
  success="A keyless deploy: badge in, image out, tasks rolled." />

<Hint>Trigger, the badge permission, the job, then the steps in deploy order.</Hint>
</Card>
