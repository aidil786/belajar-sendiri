<Card id="try-yaml" type="try">
Here is a GitLab job. Build the same job in GitHub Actions.

```yaml
test:
  image: node:24
  script:
    - npm ci
    - npm test
```

<Interactive name="YamlBuilder" workflow="CI" goal={{ order: ['push', 'job', 'checkout', 'node', 'install', 'test'] }} blocks={[

  { id: 'job', kind: 'job', label: 'Job: test', yaml: 'test:\n  runs-on: ubuntu-latest', means: 'A fresh Linux runner.' },
  { id: 'checkout', kind: 'step', label: 'Check out code', yaml: '- uses: actions/checkout@v7', means: 'GitLab copies the code for you. GitHub needs this step.' },
  { id: 'node', kind: 'step', label: 'Set up Node 24', yaml: '- uses: actions/setup-node@v7\n  with:\n    node-version: 24', means: 'Like image: node:24 in GitLab.' },

Where the story breaks: a real belt carries one dish at a time. A pipeline can run many jobs side by side. And copying a build is free, so one pack can go many places.

Jenkins usually runs on your team's own servers.

Real rep (optional): open a public GitLab project. Find its `.gitlab-ci.yml` and name its stages.
