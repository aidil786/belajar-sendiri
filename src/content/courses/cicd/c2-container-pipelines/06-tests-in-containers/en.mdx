<Card id="hook" type="hook">
The tests pass on the runner. Then the image crashes in production: a system library is missing. How could the belt catch that?

<Interactive name="Choice" options={[{ label: 'Run the tests inside the image', correct: true, why: 'Same lunchbox, same taste. Anything missing shows up in CI.' }, { label: 'Run the tests twice on the runner', why: 'The runner has things the image lacks. Twice still misses it.' }, { label: 'Test only on your laptop', why: 'Your laptop has things the image lacks too.' }]} />
</Card>

<Card id="see-stages" type="see">
<Interactive name="SpotLines" lines={[{ text: 'FROM node:24-alpine AS base' }, { text: 'WORKDIR /app' }, { text: 'COPY package*.json ./' }, { text: 'RUN npm ci' }, { text: 'COPY . .' }, { text: 'FROM base AS test', target: true }, { text: 'CMD ["npm", "test"]' }, { text: 'FROM base AS app' }, { text: 'RUN npm prune --omit=dev' }, { text: 'CMD ["node", "server.js"]' }]} prompt="Tap the line where the test stage starts." success="Yes! Same base, then a stage just for tests." />

One recipe, two dishes. The **test stage** keeps the test tools. The app stage is what customers get. Both grow from the same base layers.
</Card>

<Card id="check" type="check">
The build step says `load: true`. Why?

<Interactive name="Choice" options={[{ label: "It copies the image into the runner's Docker, so docker run finds it", correct: true, why: 'Buildx builds in its own box. load brings the image out.' }, { label: 'It uploads the image to GHCR', why: 'That is push. load keeps the image on the runner.' }, { label: 'It loads the layer cache', why: 'cache-from does that.' }]} />
</Card>

<Card id="win" type="win">
You can now run your tests inside the image you ship.
</Card>

<Card id="deeper" type="deeper">
Another way: put `RUN npm test` in the test stage. Then a failing test fails the build itself. Keep test tools out of the app stage. The shipped image stays small.
