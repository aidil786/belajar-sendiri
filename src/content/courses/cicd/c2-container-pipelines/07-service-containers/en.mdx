A **<Term id="service-container">service container</Term>** is a practice fridge wheeled next to the station. GitHub starts it before your steps. It is thrown away after the job.
</Card>

<Card id="try-fix" type="try">
Fix the yellow line: give the job a database. Then press Run.

<Interactive name="ConveyorBelt" scenario="c2-service-db" task={{ type: 'green' }} fixes={[
  { label: 'Postgres service on port 5432', text: '    runs-on: ubuntu-latest\n    services:\n      db:\n        image: postgres:18\n        env:\n          POSTGRES_PASSWORD: test\n        options: --health-cmd pg_isready --health-interval 5s --health-retries 10\n        ports:\n          - 5432:5432' },
  { label: 'Redis service on port 6379', text: '    runs-on: ubuntu-latest\n    services:\n      cache:\n        image: redis:8\n        ports:\n          - 6379:6379', why: 'Redis is a cache, not the database the tests call.' }]}
  success="Green! The tests found their database." />

<Hint>The tests call Postgres on localhost, port 5432.</Hint>
</Card>

<Card id="predict" type="predict">
Why add `options: --health-cmd pg_isready`?

<Interactive name="Choice" options={[{ label: 'The runner waits until Postgres is ready', correct: true, why: 'Postgres needs a few seconds to wake up. Without a check, tests may knock too early.' }, { label: 'It makes Postgres faster', why: 'It only checks if Postgres is ready. Speed stays the same.' }, { label: 'It hides the password', why: 'It has nothing to do with the password.' }]} />
</Card>

<Card id="win" type="win">
You can now give your tests a throwaway database.
</Card>

<Card id="deeper" type="deeper">
`test` is fine as a password here. The fridge lives for one job only. Real secrets still go in the locked spice box. Job running in a `container:`? Call the service by its name, `db`.
