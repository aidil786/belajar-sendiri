Your new checkout is half done. But main must ship today. What do you do?

<Interactive name="Choice" options={[{ label: 'Ship it, hidden behind an off switch', correct: true, why: 'The code goes live, but no user sees it yet.' }, { label: 'Wait until it is all done', why: 'Big, late merges are risky. <Card id="see-split" type="see">
<Interactive name="TimelineTap" events={[{ when: 'Tuesday', title: 'Deploy', text: 'The new checkout code goes live, switched off. Two moments, not one. To **<Term id="deploy">deploy</Term>** is to put code on the servers. To release is to let users see it.
</Card>

<Card id="predict" type="predict">
The new checkout breaks for some users. What is the fastest fix?

<Interactive name="Choice" options={[{ label: 'Turn the flag off', correct: true, why: 'One switch. No build, no deploy. Seconds, not minutes.' }, { label: 'Revert, then wait for a new deploy', why: 'That works, but a full pipeline run takes minutes.' }, { label: 'Wait for the next release', why: 'Users would keep hitting the bug until then.' }]} />
</Card>

<Card id="check-habits" type="check">
Good flag habits, or needs work? Swipe.

<Interactive name="SwipeJudge" prose cards={[{ text: 'Remove a flag once everyone has the feature.', good: true, why: 'Old flags pile up and confuse people.' }, { text: 'Keep every flag forever, just in case.', good: false, why: 'Each flag doubles the paths to test. <Card id="deeper" type="deeper">
Flags need a home and a switch. OpenFeature is an open standard many flag tools share. Cloudflare has one too, called Flagship. A flag is also a kill switch for a broken feature.

Real rep (optional): add one flag to your app as a setting. Deploy it off, then switch it on.
</Card>
