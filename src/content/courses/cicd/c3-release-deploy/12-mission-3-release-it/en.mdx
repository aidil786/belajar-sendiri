<Interactive name="ConveyorBelt" scenario="c3-mission-bad" label="Tag v1.0.1: the canary fails its smoke test, production is skipped, and rollback runs." />

Mission 3: Release it. Kedai Kancil already tests and builds itself. Now make releasing safe. Your goal: a bad release, caught and rolled back by the pipeline. Run it to see the goal.
</Card>

<Card id="try-setup" type="try">
Step 1: two kitchens. Your shop's web front end goes on Cloudflare's free Workers plan. Add this to `wrangler.jsonc`:

```jsonc
"account_id": "YOUR_ACCOUNT_ID",
"env": { "staging": {}, "production": {} }
```

<Interactive name="Mission" id="cicd-m3-setup" steps={[
  { id: 'token', text: 'Make a Cloudflare API token from the "Edit Cloudflare Workers" template. Limit it to your one account.' },
  { id: 'health', text: 'Make your built site answer /health with ok. A health.html file in the build folder works.' },
  { id: 'staging', text: 'Create the staging environment in your repo.', command: 'gh api --method PUT "repos/{owner}/{repo}/environments/staging"' },
  { id: 'production', text: 'Create production too. Then, in its settings, add yourself as a required reviewer.', command: 'gh api --method PUT "repos/{owner}/{repo}/environments/production"' },
  { id: 'secret-staging', text: 'Store the token in staging. It asks you to paste the value.', command: 'gh secret set CLOUDFLARE_API_TOKEN --env staging' },
  { id: 'secret-production', text: 'Store a token in production too.', command: 'gh secret set CLOUDFLARE_API_TOKEN --env production' },
  { id: 'vars', text: 'Save your staging address as a repository variable. Do the same for SITE_URL.', command: 'gh variable set STAGING_URL --body "https://kedai-kancil-staging.YOUR-SUBDOMAIN.workers.dev"' }]}
  success="Both kitchens are ready, each with its own locked spice box." />
</Card>

<Card id="try-build" type="try">
Step 2: build `release.yml`. Canary first. Production after it, with your approval. Rollback only if the canary fails.

<Interactive name="YamlBuilder" workflow="Release" goal={{ order: ['tag', 'perms', 'canary', 'ready1', 'stage', 'smoke', 'prod', 'ready2', 'ship', 'rollback', 'ready3', 'undo'] }} blocks={[
  { id: 'tag', kind: 'trigger', label: 'On a version tag', yaml: "push:\n  tags: ['v*']", means: 'Run when you push a tag like v1.0.0.' },
  { id: 'perms', kind: 'permissions', label: 'Read-only token', yaml: 'contents: read', means: 'The token can only read the code.' },
  { id: 'canary', kind: 'job', label: 'Job: canary (staging)', yaml: 'canary:\n  runs-on: ubuntu-latest\n  environment: staging', means: 'Try the new version on staging first.' },
  { id: 'ready1', kind: 'step', label: 'Get ready (canary)', yaml: '- uses: actions/checkout@v7\n- run: npm ci', means: 'Copy the code. Install packages.' },
  { id: 'stage', kind: 'step', label: 'Deploy to staging', yaml: '- run: npx wrangler deploy --env staging\n  env:\n    CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}', means: 'Upload to the kedai-kancil-staging Worker.' },
  { id: 'smoke', kind: 'step', label: 'Smoke test staging', yaml: '- run: curl --fail --silent "$STAGING_URL/health"\n  env:\n    STAGING_URL: ${{ vars.STAGING_URL }}', means: 'One quick taste. An error page stops the line.' },
  { id: 'loose', kind: 'job', label: 'Job: production (no needs)', yaml: 'production:\n  runs-on: ubuntu-latest\n  environment: production', means: 'Deploy to production.', why: 'Without needs: canary, production would not wait for the canary.' },
  { id: 'prod', kind: 'job', label: 'Job: production (after canary)', yaml: 'production:\n  needs: canary\n  runs-on: ubuntu-latest\n  environment:\n    name: production\n    url: ${{ vars.SITE_URL }}', means: 'Only after a green canary, and your approval.' },
  { id: 'ready2', kind: 'step', label: 'Get ready (production)', yaml: '- uses: actions/checkout@v7\n- run: npm ci', means: 'A new runner needs the code again.' },
  { id: 'ship', kind: 'step', label: 'Deploy to production', yaml: '- run: npx wrangler deploy --env production\n  env:\n    CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}', means: 'Upload to the kedai-kancil-production Worker.' },
  { id: 'rollback', kind: 'job', label: 'Job: rollback (canary failed)', yaml: 'rollback:\n  needs: canary\n  if: failure()\n  runs-on: ubuntu-latest\n  environment: staging', means: 'Runs only when the canary failed.' },
  { id: 'ready3', kind: 'step', label: 'Get ready (rollback)', yaml: '- uses: actions/checkout@v7\n- run: npm ci', means: 'Wrangler and the config, once more.' },
  { id: 'undo', kind: 'step', label: 'Roll staging back', yaml: '- run: npx wrangler rollback --env staging --message "Canary failed"\n  env:\n    CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}', means: 'Put the last good version back on staging.' }]}
  success="That is your release.yml. Save it in .github/workflows/." />

<Hint>Three jobs, each with its steps: canary, then production, then rollback.</Hint>
</Card>

<Card id="try-ship" type="try">
Step 3: ship one good release, then one bad one on purpose.

<Interactive name="Mission" id="cicd-m3-ship" steps={[

  { id: 'good', text: 'Ship a good release: make the tag v1.0.0 and push it.', command: 'git tag v1.0.0 && git push origin v1.0.0' },
  { id: 'approve', text: 'The canary passes. Production waits. Open the run and approve it.' },
  { id: 'break', text: 'Break it on purpose: delete the health page, then commit and push.' },

<Card id="deeper" type="deeper">
Safety: the free Workers plan is enough here. Containers for the API need Workers Paid. Set a budget alert first. Use test tokens and delete them when done. This canary is a staging copy. A true canary sends a share of real users. On Cloudflare, that is a gradual deployment.
</Card>
