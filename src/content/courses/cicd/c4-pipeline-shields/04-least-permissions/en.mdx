<Card id="see-least" type="see">
Each job gets a key card: the <Term id="github-token" course="git">GITHUB_TOKEN</Term>. `permissions:` picks its doors. Open only what the job needs. That is **<Term id="least-privilege">least privilege</Term>**.

One door per task." />
</Card>

<Card id="see-levels" type="see">
`permissions: {}` at the top gives no keys. Then each job asks for its own. List some keys, and every other key becomes `none`.

<Interactive name="SpotLines" lines={[{ text: 'permissions: {}' }, { text: 'jobs:' }, { text: '  test:' }, { text: '    runs-on: ubuntu-latest' }, { text: '    permissions:' }, { text: '      contents: read' }, { text: '  release:' }, { text: '    runs-on: ubuntu-latest' }, { text: '    permissions:' }, { text: '      contents: write', target: true }]} prompt="Tap the line that lets a job create a release." success="Only the release job can write. The test job can only read." />
</Card>

<Card id="try-build" type="try">
Build it. The file reads code only. The job adds one door: PR comments. Job keys replace the file's keys, so list both.

<Interactive name="YamlBuilder" workflow="PR report" goal={{ order: ['pr', 'read', 'job', 'prw', 'checkout', 'test', 'comment'] }} blocks={[

<Card id="win" type="win">
You can now give each job only the keys it needs.
</Card>

<Card id="deeper" type="deeper">
Repo settings also pick a default key: read-only, or read and write. Don't trust the default. Write `permissions:` in every workflow. Tip: split a release into a test job and a release job. Only the release job gets `contents: write`. Real rep: add `permissions:` with `contents: read` to one of your workflows.
</Card>
