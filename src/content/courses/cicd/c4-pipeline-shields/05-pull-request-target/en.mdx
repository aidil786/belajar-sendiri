<Card id="see-prt" type="see">
Some teams want previews for forks too. So they switch to **<Term id="pull-request-target">pull_request_target</Term>**. It runs with your secrets and a write key, even for forks. Sort the two triggers.

<Interactive name="SortCards" buckets={[{ id: 'pr', label: 'pull_request' }, { id: 'prt', label: 'pull_request_target' }]} items={[{ label: "Uses the workflow file from the PR's own code", bucket: 'pr', why: 'The PR can change the workflow, but forks get no secrets.' }, { label: 'Uses the workflow file from your default branch', bucket: 'prt', why: 'A stranger cannot edit it. That is why it is trusted with keys.' }, { label: 'Fork PRs: no secrets, read-only key', bucket: 'pr', why: 'The safe default for code from strangers.' }, { label: 'Fork PRs: your secrets and a write key', bucket: 'prt', why: 'Powerful, so it must never run their code.' }]} success="Sorted! One is safe for strange code. One holds your keys." />
</Card>

<Card id="try-spot" type="try">
Tap the two lines that turn this workflow into a trap.

<Interactive name="SpotTheHole" file=".github/workflows/welcome.yml" workflow={['name: Welcome', 'on:', '  pull_request_target:',

<Card id="check" type="check">
Fine on `pull_request_target`, or a trap? Swipe each job.

<Interactive name="SwipeJudge" prose cards={[{ text: 'Add a label to a fork PR, without checking out its code', good: true, why: 'Only your own trusted code runs.' }, { text: 'Check out the PR head and run `npm test`', good: false, why: 'Their code runs with your secrets and a write key.' }, { text: 'Post a fixed "Thanks!" comment', good: true, why: 'Fixed text, your code. Nothing from the stranger runs.' }, { text: "Build the PR's code for a preview, with your token", good: false, why: 'Build scripts are code. Their code would hold your token.' }]} />

<Card id="win" type="win">
You can now keep a stranger's PR away from your keys.
</Card>

<Card id="deeper" type="deeper">
Safer pattern: test fork code with `pull_request`. Need secrets afterwards? Use a separate workflow on `workflow_run`, and treat its artifacts as untrusted. First-time contributors may need a maintainer to approve their runs. Real rep: search your repos for `pull_request_target` and check each one.
</Card>
