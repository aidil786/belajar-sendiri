<Card id="try-localhost" type="try">
**<Term id="localhost">localhost</Term>** means “this computer, right here”. The shop is open at hatch 8080. `curl` fetches a page, like a tiny browser. Type `curl localhost:8080`.

<Interactive name="KitchenSim" scenario="d0-net" keys={['curl', '-I', 'localhost:8080', '127.0.0.1', 'Tab', '↑']} goal={{ lastTyped: '^curl\\b.*(localhost|127\\.0\\.0\\.1):8080', lastExit: 0 }} hints={['Type curl localhost:8080 and press Enter.']} success="The shop answered from your own laptop. localhost is you!" />

<Card id="see-dns" type="see">
<Interactive name="KitchenReplay" scenario="d0-net" commands={['cat /etc/hosts', 'curl http://kedai-kancil:8080']} fails={['curl http://kedai-kancil:8080']} label="/etc/hosts lists localhost as 127.0.0.1. Then curl says: Could not resolve host: kedai-kancil." />

**<Term id="dns">DNS</Term>** is the phone book: it turns a name into an IP address. Your laptop also keeps a tiny phone book, /etc/hosts. Nobody lists kedai-kancil, so curl gives up.
</Card>

<Card id="deeper" type="deeper">
`127.0.0.1` is localhost’s own number. In Docker output, `0.0.0.0:8080` means “port 8080 on every address of this laptop”. A browser at http://localhost:8080 asks the same as curl.

Real rep (optional): with Docker installed, run `docker run -d --name web -p 8080:80 nginx:1.30-alpine`. Open http://localhost:8080 in your browser. Clean up with `docker rm -f web`.
</Card>
