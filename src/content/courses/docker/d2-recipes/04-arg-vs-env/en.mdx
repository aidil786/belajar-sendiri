You bake the same menu for two shops: Kancil and Pasar. Only the shop name changes. Do you need two recipes?

<Interactive name="Choice" options={[{ label: 'No. Pass the shop name when you build', correct: true, why: 'One recipe, a blank to fill in at build time.' }, { label: 'Yes, one recipe per shop', why: 'That works, but every fix must be done twice.' }, { label: 'Yes, and two folders too', why: 'No need. <Card id="see-arg" type="see">
<Interactive name="KitchenReplay" scenario="d2-l04" commands={['cat Dockerfile', 'docker build --build-arg SHOP=pasar -t menu:pasar .', 'docker run --rm menu:pasar']} label="The recipe has ARG SHOP=kancil and ENV GREETING. Built with --build-arg SHOP=pasar, the image prints Menu for pasar." />

**<Term id="build-arg">ARG</Term>** is a blank for baking time. `--build-arg SHOP=pasar` fills it in. Without it, the default `kancil` is used.
</Card>

<Card id="try-build" type="try">
Build the command that bakes a menu for Pasar.

<Interactive name="CommandBuilder" pieces={[{ text: 'docker build', means: 'bake an image' }, { text: '--build-arg SHOP=pasar', means: 'fill the SHOP blank' }, { text: '-t menu:pasar', means: 'name and tag' }, { text: '.', means: 'this folder' }]} decoys={[{ text: '-e SHOP=pasar', means: '-e is for docker run, not build' }]} success="That bakes the Pasar menu." />

<Card id="try-env" type="try">
`ENV GREETING` does stay in the pack. Print it. Then change it with `-e` and print it again.

<Interactive name="KitchenSim" scenario="d2-l04" intro={['docker build -t menu:1.0 .']} goal={{ typed: '-e GREETING=', lastTyped: 'printenv GREETING' }} hints={['Type docker run --rm menu:1.0 printenv GREETING', 'Now: docker run --rm -e GREETING=Hai menu:1.0 printenv GREETING']} success="ENV gives the default. -e changes it for one box." />

<Card id="win" type="win">
You can now pick ARG for baking and ENV for running.
</Card>

<Card id="deeper" type="deeper">
Never pass a password with ARG or ENV. `docker history` shows ARG values, and ENV stays in every container. Lesson 12 shows the safe way: build secrets.

An `ARG` before `FROM` can pick the base itself: `ARG BASE=nginx:latest`, then `FROM ${BASE}`. Lesson 9 uses this trick.
