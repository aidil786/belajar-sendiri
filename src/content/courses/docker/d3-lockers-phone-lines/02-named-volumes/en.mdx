<Card id="see-volume" type="see">
A **<Term id="volume">volume</Term>** is a locker outside the lunchbox. Docker keeps it until you delete it. Tap the pieces to build a database with a locker.

<Interactive name="CommandBuilder" pieces={[{ text: 'docker run -d', means: 'Start a box in the background' }, { text: '--name db', means: 'Call it db' }, { text: '-e POSTGRES_PASSWORD=secret', means: 'Postgres needs a password' }, { text: '-v pgdata:/var/lib/postgresql', means: 'Locker pgdata, opened at the data folder' }, { text: 'postgres:18-alpine', means: 'The meal pack to use' }]} decoys={[{ text: '-v pgdata:/var/lib/postgresql/data', means: 'The folder older Postgres used. Postgres 18 refuses it.' }]} success="That's it! -v name:folder gives the box a locker." />
</Card>

<Card id="check" type="check">
Which command deletes the orders for good?

<Interactive name="Choice" options={[{ label: '`docker rm -f db`', why: 'The lunchbox goes. The pgdata locker stays.' }, { label: '`docker volume rm pgdata`', correct: true, why: 'Yes. It empties the locker for good. Docker refuses while a box still uses it.' }, { label: '`docker restart db`', why: 'Same box, same locker. Nothing is lost.' }]} />
</Card>

<Card id="win" type="win">
You can now keep data in a locker that outlives the container.
</Card>

<Card id="deeper" type="deeper">
Real error: `volume is in use`. Plain words: remove the box first. Without `-v`, Postgres gets a nameless locker. A new box gets a new one, so `docker volume ls` collects leftovers.

<Interactive name="KitchenReplay" scenario="d3-pg-orders" commands={['docker volume ls', 'docker volume rm pgdata']} fails={['docker volume rm pgdata']} label="docker volume ls lists pgdata. docker volume rm pgdata is refused: the volume is in use by the db container." />
