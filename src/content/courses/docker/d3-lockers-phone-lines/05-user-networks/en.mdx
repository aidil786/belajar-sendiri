A **<Term id="user-network">network</Term>** is a phone line between lunchboxes. `docker network create shopnet` makes your own line. Docker made the other three for you.
</Card>

<Card id="try-network" type="try">

<Hint>`docker network connect shopnet web` plugs in a box that is already running.</Hint>

<Card id="predict" type="predict">
cache starts with a plain `docker run`, no `--network`. Can it call menu, which is on shopnet?

<Interactive name="Choice" options={[{ label: 'No: cache is on the default line', correct: true, why: 'Each network is its own line. cache is not on shopnet.' }, { label: 'Yes: all boxes share one line', why: 'Only boxes on the same network can talk.' }, { label: 'Only after a restart', why: 'A restart keeps the same lines. network connect adds one.' }]} />
</Card>

<Card id="see-connect" type="see">
<Interactive name="KitchenReplay" scenario="d3-shopnet" commands={['docker exec cache wget -qO- http://menu', 'docker network connect shopnet cache', 'docker exec cache sh -c "wget -qO- http://menu | grep title"']} fails={['docker exec cache wget -qO- http://menu']} label="cache can't find menu. `docker network connect` plugs a running box into a line. No restart needed. Now cache can call menu.
</Card>

<Card id="win" type="win">
You can now give your containers their own phone line.
</Card>

<Card id="deeper" type="deeper">
The default bridge has no names, and every box lands on it. Your own network has names, and only invited boxes. `docker network inspect shopnet` lists who is plugged in. `docker network disconnect` unplugs a box.
