<Card id="see-hatch" type="see">

To **publish** a port (`-p 8080:80`) opens a <Term id="port-mapping">hatch</Term> on your laptop. `EXPOSE 80` in a recipe only writes the port on the label.
</Card>

<Card id="predict" type="predict">
db shows `5432/tcp`, with no `-p`. Who can reach it?

<Card id="try-publish" type="try">
Give web a hatch on 8080. A box can't get a new hatch later, so make it again.

<Interactive name="KitchenSim" scenario="d3-expose" goal={{ portMapped: { web: '8080:80' }, reachable: 'localhost:8080' }} hints={['Type docker rm -f web', 'Type docker run -d --name web -p 8080:80 nginx:1.30-alpine', 'Then curl localhost:8080']} success="Hatch 8080 is open. The page comes through." />

<Hint>Hatches are set when a box is made. Remove web, then run it with `-p 8080:80`.</Hint>
</Card>

<Card id="see-modes" type="see">
Each box gets a line type. The default is bridge. **host** shares your laptop's own line. none has no line at all. Sort them.

<Interactive name="SortCards" buckets={[{ id: 'bridge', label: 'bridge (default)' }, { id: 'host', label: 'host' }, { id: 'none', label: 'none' }]} items={[{ label: 'Its own line; your laptop reaches it through -p', bucket: 'bridge', why: 'The normal setup. Hatches decide what your laptop sees.' }, { label: "Uses the laptop's ports directly", bucket: 'host', why: 'The app listens straight on your laptop.' }, { label: '-p is thrown away', bucket: 'host', why: 'No hatch is needed, so Docker drops -p with a warning.' }, { label: 'Only loopback inside', bucket: 'none', why: 'Not even the internet. Good for offline jobs.' }]} success="bridge, host, none: three kinds of line." />
</Card>

<Card id="check-host-none" type="check">
<Interactive name="KitchenReplay" scenario="d3-expose" commands={['docker run -d --name hostbox --network host -p 8082:80 alpine:3.22 sleep 300', 'docker run --rm --network none alpine:3.22 ping -c 1 8.8.8.8']} fails={['docker run --rm --network none alpine:3.22 ping -c 1 8.8.8.8']} label="host mode prints: WARNING: Published ports are discarded when using host network mode. With none, ping says: Network unreachable." />

Real words from Docker: host mode discards `-p`. With none, `Network unreachable`: the box has no line out.
</Card>

<Card id="win" type="win">
You can now choose which ports your laptop can reach.
</Card>

<Card id="deeper" type="deeper">
`-p 8080:80` listens on every network card, so your Wi-Fi neighbours may reach it too. `-p 127.0.0.1:8080:80` keeps the hatch for your laptop only. `-P` opens a random hatch for each exposed port. On Docker Desktop, host mode needs a recent version; check the docs.
