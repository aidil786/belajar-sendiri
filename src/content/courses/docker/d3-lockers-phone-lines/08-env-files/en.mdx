An **<Term id="env-file">env file</Term>** is a settings card: one `NAME=value` per line. `--env-file shop.env` hands the whole card to the box.
</Card>

<Card id="check-error" type="check">
<Interactive name="KitchenReplay" scenario="d3-envfile" commands={['cat spaces.env', 'docker run --rm --env-file spaces.env alpine:3.22 env']} fails={['docker run --rm --env-file spaces.env alpine:3.22 env']} label="spaces.env has SHOP_NAME = Kedai Kancil. docker run refuses it: variable 'SHOP_NAME ' contains whitespaces." />

Real error: `variable 'SHOP_NAME ' contains whitespaces`. Plain words: no spaces around the = sign.
</Card>

<Card id="win" type="win">
You can now hand a container its settings in one file.
</Card>

<Card id="deeper" type="deeper">
A line with only `NAME` copies that value from your laptop, if it is set. Compose reads `.env` files with its own rules: World D4. Does your env file hold a password? Keep it out of Git: put it in `.gitignore`.
