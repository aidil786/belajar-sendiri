<Card id="see-order" type="see">
```yaml
  web:
    depends_on: [api]
  api:
    depends_on: [db]
```

<Interactive name="OrderList" items={['db', 'api', 'web']} label="First to start at the top" success="db, then api, then web." />

**<Term id="depends-on">depends_on</Term>** sets the start order. A dish starts after the dishes it depends on. Put the start order right.
</Card>

<Card id="see-healthy" type="see">
```yaml
  api:
    depends_on:
      db:
        condition: service_healthy
  db:
    image: postgres:18-alpine
    healthcheck:
      test: ["CMD", "pg_isready", "-U", "postgres"]
      interval: 2s
      retries: 10
```

<Interactive name="KitchenReplay" scenario="d4-healthy" commands={['docker compose up -d']} label="db shows Healthy first. Only then do api and web start." />

Started is not ready. A health check is a taste test. `pg_isready` asks db: ready yet? `service_healthy` makes api wait for a yes.
</Card>

<Card id="try-wait" type="try">

<Card id="deeper" type="deeper">
Three conditions: `service_started` (the short list form), `service_healthy`, and `service_completed_successfully` for a one-off job, like making tables. Add `restart: true` and Compose also restarts api after it restarts db. `docker compose up -d --wait` returns only when every dish is running or healthy. CI uses it.
