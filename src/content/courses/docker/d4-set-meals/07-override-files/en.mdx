<Card id="see-override" type="see">
```yaml
# compose.override.yaml
services:
  web:
    volumes:
      - ./web:/usr/share/nginx/html:ro
```

<Interactive name="KitchenReplay" scenario="d4-override" commands={['docker compose up -d', 'echo "<h1>Kedai Kancil: new menu</h1>" > web/index.html', 'curl -s localhost:8080']} label="The laptop's web folder is mounted into web, so the new menu shows at once." />

Shared things stay in `compose.yaml`. Laptop extras go in `compose.override.yaml`. Compose reads this **<Term id="compose-override">override file</Term>** by itself and lays it on top.
</Card>

<Card id="predict" type="predict">
Two files set the same key. The first says one value, the later file says another. Which one wins?

<Interactive name="Choice" options={[{ label: 'The later file', correct: true, why: 'Files stack in order. Later files change it.' }, { label: 'Compose stops with an error', why: 'Changing a value is the whole point. Compose merges the files.' }]} />
</Card>

<Card id="try-prod" type="try">
Start the server version: `compose.yaml` plus `compose.prod.yaml`. Name both files with `-f`, base first.

<Card id="check-prod" type="check">
<Interactive name="KitchenReplay" scenario="d4-override" commands={['docker compose -f compose.yaml -f compose.prod.yaml up -d', 'echo "<h1>Kedai Kancil: new menu</h1>" > web/index.html', 'curl -s localhost:8080']} label="With -f, the dev override is skipped. The laptop edit doesn't reach the server: the old page shows." />

Why the old page? With `-f`, Compose reads only the files you name. No dev mount, so the page comes from the image.
</Card>

<Card id="win" type="win">
You can now run one app two ways: dev and prod.
</Card>

<Card id="deeper" type="deeper">
How files merge: one value (like `image`) is replaced. Lists like `ports` are added together. `environment` merges by name. `volumes` merge by the path inside the box. Dry run the mix before you start it: `docker compose -f compose.yaml -f compose.prod.yaml config`.
