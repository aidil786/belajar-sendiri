`latest` cuma nama label. Ia bukan bermaksud terbaru atau sudah diuji. **<Term id="tag">Tag</Term>** pindah ke apa sahaja yang anda bina paling akhir.
</Card>

<Card id="sort-tags" type="try">

<Card id="try-tags" type="try">
Beri satu binaan dua tag yang bagus: versi dan commit Git. Satu `docker build` boleh ambil dua `-t`.

<Interactive name="KitchenSim" scenario="d5-tags" goal={{ imageExists: ['kedai-api:1.4.2', 'kedai-api:sha-3f9c2e1'] }} hints={['Guna -t dua kali: -t kedai-api:1.4.2 -t kedai-api:sha-3f9c2e1', 'Taip docker build -t kedai-api:1.4.2 -t kedai-api:sha-3f9c2e1 .']} success="Dua label, satu pek. Kedua-duanya namakan keluaran yang sama." />

<Hint>`docker build -t kedai-api:1.4.2 -t kedai-api:sha-3f9c2e1 .` Titik itu bermaksud "folder ini".</Hint>
</Card>

<Card id="predict" type="predict">
`kedai-api:1.4.2` ada dalam production. Anda baiki satu salah ejaan. Tag apa untuk pembaikan itu?

<Interactive name="Choice" options={[{ label: '`1.4.3`, versi baru', correct: true, why: 'Versi yang sudah keluar tak pernah berubah. </Card>

<Card id="win" type="win">
Kini anda boleh tag image supaya production sentiasa tahu apa yang ia jalankan.
</Card>

<Card id="deeper" type="deeper">
Ramai pasukan juga push tag bergerak seperti `1.4` dan `1`, untuk orang yang mahu kemas kini. Production patut tetap guna versi penuh, atau digest (pelajaran seterusnya). Dalam CI, `docker/metadata-action` buat tag ini daripada tag Git anda ([Bahagian 2, Dunia C2](/ms/cicd/#world-2)).

Latihan sebenar (pilihan), dalam folder yang ada Dockerfile dan sekurang-kurangnya satu commit Git:
