One image, two boxes, tiny extra disk. The image layers are read-only kek lapis. Each box gets a clear sheet on top. That stack is the **<Term id="overlay-filesystem">overlay filesystem</Term>**.

<Card id="predict" type="predict">

<Card id="check-diff" type="check">
<Interactive name="Transcript" title="bash" label="Real output on Docker 29: a box adds a note, deletes /etc/motd and edits /etc/profile. docker diff lists C, A and D lines." lines={[{ cmd: "docker run --name box alpine:3.22 sh -c 'echo hi > /root/note.txt; rm /etc/motd; echo hi >> /etc/profile'" }, { cmd: 'docker diff box' }, { out: 'C /etc\nC /etc/profile\nD /etc/motd\nC /root\nA /root/note.txt' }]} />

`docker diff` reads the top sheet. A = added, C = changed, D = deleted. A delete leaves a hiding sticker, called a **whiteout**. The image still has the file.
</Card>

<Card id="deeper" type="deeper">
In OverlayFS words: image layers are `lowerdir`, the sheet is `upperdir`, and the box sees `merged`. Fresh Docker Engine 29 installs use the containerd image store with its `overlayfs` snapshotter. Upgraded older installs may say `overlay2`. Check with `docker info`.
