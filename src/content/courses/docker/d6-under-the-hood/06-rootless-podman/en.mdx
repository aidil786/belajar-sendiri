By default, root inside a container is root on the laptop too. A bug lets an app break out of its box. What can it do?

<Interactive name="Choice" options={[{ label: 'Anything root can do on the laptop', correct: true, why: 'Without a user namespace, root inside is the real root.' }, { label: 'Only touch files inside its box', why: 'It broke out, so the box no longer holds it.' }, { label: 'Nothing. Containers are virtual machines.', why: 'They are processes on the laptop’s own kernel.' }]} />
</Card>

<Card id="see-userns" type="see">
<Interactive name="NamespaceXray" switches={['user']} task={{ type: 'turnOn', switches: ['user'] }} prompt="Flip the User switch. Watch the uid on the laptop." success="Root inside, an ordinary user outside." />

Root inside now maps to uid 100000 outside. That is a **<Term id="user-namespace">user namespace</Term>**. Docker leaves it off unless you ask.
</Card>

<Card id="see-rootless" type="see">
<Interactive name="Transcript" title="bash" label="From the Docker docs: the rootless setup tool, run as a normal user, creates a CLI context called rootless and switches to it." lines={[{ cmd: 'dockerd-rootless-setuptool.sh install' }, { out: '[INFO] Creating CLI context "rootless"\nSuccessfully created context "rootless"\n[INFO] Using CLI context "rootless"\nCurrent context is now "rootless"', color: 'green' }]} />

**<Term id="rootless-mode">Rootless mode</Term>** goes further. The Docker daemon itself runs as you, inside a user namespace. A break-out gets only your rights.
</Card>

<Card id="deeper" type="deeper">
Rootless needs `newuidmap` and `newgidmap` (the `uidmap` package) and 65,536 spare ids in `/etc/subuid` and `/etc/subgid`. Limits like `--memory` need cgroup v2 with systemd. Low ports need the tips page. For Podman, `alias docker=podman` covers most commands.
