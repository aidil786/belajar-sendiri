<Card id="see-golden" type="see">
<Interactive name="GraphScene" scenario="w03-l10" commands={['git rebase main']} showLost label="Selepas rebase, salinan baru commit about duduk selepas main. Commit lama tertinggal sebagai titik putus-putus." />

Rebase buat salinan baru. Commit lama kekal pada sesiapa yang memilikinya. Dua versi! Jadi jangan rebase commit yang orang lain dah ada. Itulah **<Term id="golden-rule">peraturan emas</Term>**.
</Card>

Kadang-kadang anda cuma perlu satu commit. `git cherry-pick` salin satu commit ke branch anda. Petik satu ceri, bukan seluruh pokok. Itulah **<Term id="cherry-pick">cherry-pick</Term>**.
</Card>

<Card id="deeper" type="deeper">
Ramai pasukan rebase branch sendiri dulu, kemudian merge. Dua-dua okey asalkan ikut peraturan emas. `git cherry-pick -x` tambah satu baris yang beritahu dari mana salinan itu datang. Bertembung? Baiki fail, `git add`, kemudian `git cherry-pick --continue`. Atau `git cherry-pick --abort`.
</Card>
