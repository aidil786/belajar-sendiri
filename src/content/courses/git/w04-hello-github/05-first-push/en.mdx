<Card id="hook" type="hook">
Your diary has 3 commits. Your GitHub repo is empty. What carries the commits up there?

<Interactive name="Choice" options={[{ label: '`git push`', correct: true, why: 'Push sends commits to a remote. Watch it on the next card.' }, { label: '`git commit`', why: 'A commit saves on your laptop only.' }, { label: 'GitHub copies them by itself', why: 'GitHub cannot see your laptop. You send them.' }]} />
</Card>

<Card id="see-push" type="see">
<Interactive name="Courier" scenario="w04-l05" commands={['git push -u origin main']} label="A courier carries three commits from your laptop to the empty GitHub repo. Now GitHub's main matches yours, and your laptop shows origin/main." />

A **<Term id="push">push</Term>** is a courier. It carries your new commits up to GitHub. `git push -u origin main` sends main to origin.
</Card>

<Card id="see-upstream" type="see">
<Interactive name="TermReplay" scenario="w04-l05" commands={['git push -u origin main', 'git status']} label="The push says main set up to track origin/main. Then git status says: Your branch is up to date with origin/main." />

`-u` sets the **<Term id="upstream">upstream</Term>**: main now follows `origin/main`. From now on, plain `git push` knows where to go.
</Card>

</Card>

<Card id="deeper" type="deeper">
`git config --global push.autoSetupRemote true` makes plain `git push` set the upstream for new branches too. `git push origin --delete old-branch` deletes a branch on GitHub. Pushing a new branch makes GitHub print a pull request link.
</Card>
