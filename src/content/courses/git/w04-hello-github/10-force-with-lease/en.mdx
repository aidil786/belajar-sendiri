You pushed "Add about pgae". Oops! You fixed the message with `--amend`. Now `git push` is rejected. `git push --force` is tempting. What's the risk?

<Interactive name="Choice" options={[{ label: 'It can wipe commits others pushed', correct: true, why: 'Force does not look. It just replaces. Watch it happen next.' }, { label: 'None. </Card>

<Card id="try-build" type="try">
Build the safer force push.

<Hint>Look for the one with a lease.</Hint>

<Card id="see-lease" type="see">
<Interactive name="Courier" scenario="w04-l10-team" commands={['git push --force-with-lease']} label="git push --force-with-lease checks GitHub first. GitHub moved since your last fetch, so the push stops and the parcel comes back. Aisyah's commit stays." />

`--force-with-lease` checks first. Is GitHub still where my last fetch saw it? Aisyah pushed since, so it stops. Her work stays safe.

<Card id="win" type="win">
You can now force push only when it's safe, with --force-with-lease.
</Card>

<Card id="deeper" type="deeper">
The lease trusts your `origin/main`. Some editors fetch quietly in the background, which updates it. Then the lease may pass without you seeing the new commits. `--force-if-includes` adds one more check for that. Shared mistakes on main? Use `git revert` instead.
</Card>
