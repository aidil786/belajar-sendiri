An **<Term id="issue-template">issue template</Term>** is a form with blanks. It lives in `.github/ISSUE_TEMPLATE/`. Every new bug report starts with these questions.
</Card>

<Card id="try-fill" type="try">
Help Sam. Fill in the template for the bug: the sign-up button does nothing.

<Interactive name="MarkdownPlayground" initial={'## What happened?\n\n## Steps to see it\n1.\n\n## Phone or computer?\n'} prompt="Fill all three blanks." goal={{ mustMatch: ['^## What happened\\?[ \\t]*\\n+[ \\t]*[^#\\s]', '^1\\.[ \\t]+\\S', '^## Phone or computer\\?[ \\t]*\\n+[ \\t]*[^#\\s]'], hint: ['Write one line under What happened?', 'After 1. write the first step, like: Open the home page.', 'Write a line under the last heading, like: Android phone.'] }} success="Now anyone can see the bug in one read." />

<Hint>Short answers are fine: "Nothing happens when I tap Sign up."</Hint>
</Card>

<Card id="deeper" type="deeper">
Templates can also be issue forms: `.yml` files with real form fields. A `config.yml` in the same folder sets up the template chooser. A pull request template (`pull_request_template.md`) fills new PR descriptions. Sub-issues can have their own sub-issues. Issue types are set up in an organization's settings.
</Card>
