**<Term id="git-flow">Git Flow</Term>** spreads work over five kinds of branch. Two live forever: main and develop. The rest come and go. Tap to follow version 2.1.
</Card>

<Card id="see-release" type="see">
<Interactive name="AreasScene" zoneLabels={{ working: 'develop', staging: 'release/2.1.0', repo: 'main' }} label="Two features, Add map screen and Add login, move from develop into release/2.1.0 for testing. Features done? Start a **<Term id="release-branch">release branch</Term>** from develop. Testers check it there. Then it merges into main, with a version tag.
</Card>

<Card id="deeper" type="deeper">
The author of Git Flow added a note in 2020. Web apps that ship all the time may not need it. He suggests something simpler, like GitHub Flow. Git Flow still suits software with numbered versions. Git's own project uses a different model. Read gitworkflows to see it.
</Card>
