**<Term id="semantic-versioning">Semantic Versioning</Term>** (SemVer) uses three numbers: MAJOR.MINOR.PATCH. Each one tells users how big the change is.
</Card>

<Card id="try-spot" type="try">
**<Term id="conventional-commits">Conventional Commits</Term>** labels match those numbers. `fix:` means PATCH. `feat:` means MINOR. Tap every commit that adds a feature.

<Interactive name="SpotLines" scenario="w06-l05" commands={['git log --oneline']} targets=" feat: " prompt="Tap every commit that adds a feature." success="Two features! So the next version bumps MINOR." />
</Card>

You can now turn commit labels into versions and a changelog.

<Card id="deeper" type="deeper">
Tools can read Conventional Commits for you. They pick the next version and draft the changelog. A footer that starts with `BREAKING CHANGE:` also means MAJOR. Versions below 1.0.0 are for early work: anything may change. A tag like v2.5.0 adds a v, but the version is 2.5.0.
</Card>
