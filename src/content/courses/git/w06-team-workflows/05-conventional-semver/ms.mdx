**<Term id="semantic-versioning">Semantic Versioning</Term>** (SemVer) guna tiga nombor: MAJOR.MINOR.PATCH. Setiap satu beritahu pengguna sebesar mana perubahan itu.
</Card>

<Card id="try-spot" type="try">
Label **<Term id="conventional-commits">Conventional Commits</Term>** padan dengan nombor itu. `fix:` maksudnya PATCH. `feat:` maksudnya MINOR. Ketik setiap commit yang tambah ciri baru.

<Interactive name="SpotLines" scenario="w06-l05" commands={['git log --oneline']} targets=" feat: " prompt="Ketik setiap commit yang tambah ciri baru." success="Dua ciri! Jadi versi seterusnya naikkan MINOR." />
</Card>

<Card id="try-changelog" type="try">
**<Term id="changelog">Changelog</Term>** (log perubahan) senaraikan perubahan untuk manusia. Versi terbaru di atas. Perubahan dikumpul, contohnya Added dan Fixed. Ketik setiap pembaikan.

<Interactive name="SpotLines" lines={[{ text: '# Changelog' }, { text: '## [Unreleased]' }, { text: '## [2.5.0] - 2026-10-30' }, { text: '### Added' }, { text: '- Search box on the menu.' }, { text: '### Fixed' }, { text: '- Cart keeps its items.', target: true }, { text: '## [2.4.1] - 2026-10-02' }, { text: '### Fixed' }, { text: '- Prices round correctly.', target: true }]} prompt="Ketik setiap pembaikan dalam changelog ini." success="Jumpa! Orang baca ini, bukan log mentah." />
</Card>

<Card id="deeper" type="deeper">
Ada alat yang boleh baca Conventional Commits untuk anda. Ia pilih versi seterusnya dan draf changelog. Footer yang bermula dengan `BREAKING CHANGE:` juga maksudnya MAJOR. Versi bawah 1.0.0 untuk kerja awal: apa-apa boleh berubah. Tag macam v2.5.0 tambah huruf v, tapi versinya 2.5.0.
</Card>
