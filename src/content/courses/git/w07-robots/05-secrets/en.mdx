<Card id="hook" type="hook">
Your deploy needs a Cloudflare token. Paste it into `ci.yml`? Anyone who can read your repo would see it. Where should it go?

<Interactive name="Choice" options={[{ label: 'Right in the workflow file', why: 'Everyone who reads the file gets your token.' }, { label: 'In a repo secret on GitHub', correct: true, why: "GitHub locks it away. Workflows can use it. People can't read it." }, { label: 'In the commit message', why: 'Commit messages are public history. Never there.' }]} />
</Card>

<Card id="see-secret" type="see">
<Interactive name="Transcript" title="Run log" label="A step prints the token by mistake. The log shows three stars instead of the token." lines={[{ cmd: 'echo "Token: $CLOUDFLARE_API_TOKEN"' }, { out: 'Token: ***', color: 'yellow' }]} />

A **<Term id="secret">secret</Term>** waits, locked, in your repo settings. A workflow reads it by name, like `${{ secrets.MY_TOKEN }}`. Printed by mistake? The log shows `***`. Still, never print it.
</Card>

<Card id="see-variable" type="see">
Not every setting is secret. A site address is fine to show. Store it as a **<Term id="variable">variable</Term>**, and read it as `${{ vars.SITE_URL }}`. Sort these.

<Interactive name="SortCards" buckets={[{ id: 'secret', label: 'Secret' }, { id: 'var', label: 'Variable' }]} items={[{ label: 'Cloudflare API token', bucket: 'secret', why: 'It can change your site. Lock it away.' }, { label: 'Database password', bucket: 'secret', why: 'It opens all your data.' }, { label: "The site's public address", bucket: 'var', why: 'Everyone can see it anyway.' }, { label: 'Which Node version to use', bucket: 'var', why: 'Nothing to hide. A variable is fine.' }]} success="Sorted! Secrets for keys. Variables for plain settings." />
</Card>

<Card id="see-env" type="see">
An **<Term id="environment">environment</Term>** is a named place you deploy to, like `production`. It can hold its own secrets. It can wait for a person to approve. Put a guarded deploy in order.

<Interactive name="OrderList" items={['The deploy job starts, then waits', 'A reviewer checks it and approves', 'The job gets the production secrets', 'The new site goes live']} label="First step at the top" success="Yes! No approval, no secrets, no deploy." />
</Card>

Build the deploy workflow. Keys must come from secrets.

<Card id="deeper" type="deeper">
Secrets live at three levels: organization, repository and environment. Environment secrets only reach jobs that use that environment. Environment rules can also limit deploys to `main`. On GitHub's free plan, environments only work in public repos.
</Card>
