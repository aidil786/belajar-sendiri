<Card id="try-pages" type="try">
**GitHub Pages** hos laman web terus dari repo anda. Tetapkan sumbernya kepada GitHub Actions. Kemudian bina workflow ini: bungkus laman, kemudian deploy.

<Interactive name="YamlBuilder" workflow="Pages" goal={{ order: ['push', 'perms', 'job', 'checkout', 'node', 'build', 'upload', 'deploy'] }} blocks={[

  { id: 'job', kind: 'job', label: 'Job: deploy ke github-pages', yaml: 'deploy:\n  runs-on: ubuntu-latest\n  environment:\n    name: github-pages\n    url: ${{ steps.deployment.outputs.page_url }}', means: 'Runner baru, deploy ke environment github-pages.' },
  { id: 'checkout', kind: 'step', label: 'Ambil kod', yaml: '- uses: actions/checkout@v7', means: 'Salin kod anda ke runner.' },

<Card id="see-cloudflare" type="see">
Cloudflare pun hos laman. Kursus ini duduk di sana! Alatnya, Wrangler, muat naik laman anda. Dalam workflow, ia baca dua rahsia: `CLOUDFLARE_API_TOKEN` dan `CLOUDFLARE_ACCOUNT_ID`. Bina arahannya.

<Card id="deeper" type="deeper">
`id-token: write` biar Pages semak bahawa deploy betul-betul datang dari workflow anda. Tiada kunci tersimpan diperlukan. Pages perlu sumbernya ditetapkan kepada GitHub Actions dalam tetapan repo. Cloudflare juga ada action sendiri, `cloudflare/wrangler-action`, yang jalankan Wrangler untuk anda.
</Card>
