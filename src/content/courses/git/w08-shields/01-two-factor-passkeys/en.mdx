<Card id="see-2fa" type="see">
<Interactive name="TimelineTap" events={[{ when: 'Step 1', title: 'Your password', text: 'Something you know.' }, { when: 'Step 2', title: 'A code or a tap', text: 'From your phone or a security key. **<Term id="two-factor">Two-factor authentication</Term>** (2FA) asks for two proofs. First your password. Then a code or a tap from something you own.
</Card>

<Card id="try-sort" type="try">
Good 2FA mixes two kinds of proof. Sort each one.

<Interactive name="SortCards" buckets={[{ id: 'know', label: 'Something you know' }, { id: 'have', label: 'Something you have' }]} items={[{ label: 'Your password', bucket: 'know', why: 'It lives in your head.' }, { label: 'A code from an authenticator app', bucket: 'have', why: 'Only the app on your phone makes it.' }, { label: 'A security key you plug in', bucket: 'have', why: 'A small device on your keyring.' }, { label: 'A PIN', bucket: 'know', why: 'You remember it.' }, { label: 'A code sent by text message', bucket: 'have', why: 'It arrives on your own phone.' }]} success="Sorted! Two different kinds make a strong lock." />

<Hint>Ask: do I remember it, or do I hold it?</Hint>
</Card>

<Card id="see-passkey" type="see">
A **<Term id="passkey">passkey</Term>** lives on your phone, laptop or password manager. You unlock it with your face, finger or PIN. No password to type. One step, and it counts as 2FA too.
</Card>

<Card id="predict" type="predict">
A fake site looks just like GitHub. It asks you to sign in with your passkey. What happens?

<Interactive name="Choice" options={[{ label: 'The passkey refuses: wrong website', correct: true, why: 'A passkey is tied to the real site. Your browser will not use it on a fake one.' }, { label: 'The fake site steals your passkey', why: 'The passkey never leaves your device. Only a proof goes out.' }, { label: 'The fake site gets a code it can reuse', why: 'That can happen with typed codes. A passkey only works on the real site.' }]} />
</Card>

<Card id="deeper" type="deeper">
GitHub requires 2FA from people who contribute code on github.com. Lost your phone and your recovery codes too? GitHub Support cannot let you back in. So guard those codes well. A passkey can sync across your devices. Or it can stay on one security key.
</Card>
