<Card id="hook" type="hook">
Your script needs the newest commit id. `git log` prints too much, and its look can change. What should the script use?

<Interactive name="Choice" options={[{ label: 'A command made for scripts: git rev-parse HEAD', correct: true, why: 'It prints just the id, and its output stays steady.' }, { label: 'Copy the id by hand each time', why: 'A script cannot copy by hand. Git has commands for scripts.' }, { label: 'Cut the id out of git status', why: 'git status is made for people. Its words may change.' }]} />
</Card>

<Card id="see-plumbing" type="see">
<Interactive name="TermReplay" scenario="w10-plumbing" commands={['git rev-parse HEAD', 'git ls-tree HEAD']} label="git rev-parse HEAD prints one full id. git ls-tree HEAD lists about.html, the css tree and index.html, each with mode, type and id." />

Low-level commands are **<Term id="plumbing">plumbing</Term>**: the pipes under the sink. They print plain, steady output. Scripts love them.
</Card>

<Card id="try-sort" type="try">
The shiny sink on top is **<Term id="porcelain">porcelain</Term>**: commands for people. Sort each command.

<Interactive name="SortCards" buckets={[{ id: 'porcelain', label: 'porcelain (for people)' }, { id: 'plumbing', label: 'plumbing (for scripts)' }]} items={[{ label: 'git status', bucket: 'porcelain', why: 'Friendly words and colours, for you to read.' }, { label: 'git cat-file', bucket: 'plumbing', why: 'It prints raw objects.' }, { label: 'git commit', bucket: 'porcelain', why: 'An everyday command that does many steps for you.' }, { label: 'git hash-object', bucket: 'plumbing', why: 'It prints the id for some content. Porcelain for people, plumbing for scripts and the curious." />
</Card>

<Card id="see-hash-object" type="see">
<Interactive name="TermReplay" scenario="w10-plumbing" commands={['git hash-object index.html', 'git rev-parse HEAD:index.html']} label="git hash-object index.html and git rev-parse HEAD:index.html print the same id, 6b62adb46423f92b1c925e6fdcc9ec947097a1d4." />

`git hash-object` prints the id Git would give a file. It matches the blob already in the commit. Same content, same id.
</Card>

<Card id="try-write" type="try">
`notes.txt` is not in Git yet. Save its content as a blob, with no commit. Then read the blob back.

<Interactive name="Sim" scenario="w10-plumbing" panels={[]} goal={{ objectsWritten: ['17e284d'], lastTyped: 'cat-file -p' }} hints={['Add -w to write it: git hash-object -w notes.txt', 'Then type git cat-file -p and the id it printed']} success="Saved and read back! <Hint>Type `git hash-object -w notes.txt`. Then `git cat-file -p` with the id it printed.</Hint>

Ben has the same `notes.txt` on his laptop. He runs `git hash-object notes.txt`. What id does he get?

<Card id="deeper" type="deeper">
Porcelain output may change between Git versions. Plumbing output stays steady. Need status in a script? `git status --porcelain` gives a format that is promised to stay the same. `git ls-tree -r --name-only HEAD` lists every file in a commit.

<Interactive name="TermReplay" scenario="w10-plumbing" commands={['git ls-tree -r --name-only HEAD']} label="git ls-tree -r --name-only HEAD lists about.html, css/style.css and index.html." />
</Card>
