<Card id="hook" type="hook">
Your teammate's pull request changes 2,000 lines in 40 files. The reviewers sigh. Which PR gets a careful review sooner?

<Interactive name="Choice" options={[{ label: 'Fix the login button: 40 lines', correct: true, why: 'Small and focused. A reviewer can read it in minutes.' }, { label: 'Login fix + new theme + renamed files: 2,000 lines', why: 'Too many ideas at once. Reviews get slow and shallow.' }]} />
</Card>

<Card id="see-small" type="see">
<Interactive name="SpotLines" lines={[{ text: 'PR: Fix the login button' }, { text: '- Enter key submits the form' }, { text: '- Rename every CSS file', target: true }, { text: '- Warn if password is empty' }, { text: '- Add a new purple theme', target: true }]} prompt="Tap the changes that belong in a different PR." success="Yes! Those two get their own PRs." />

One PR, one purpose. A **small PR** is quick to read and easy to approve. Split the rest out.
</Card>

<Card id="try-review" type="try">
Review the code, never the person. Is each review comment kind and useful?

<Interactive name="SwipeJudge" prose cards={[{ text: '"Nice fix! Could we call this `saveDraft`? It says what it does."', good: true, why: 'Kind, specific, and it gives a reason.' }, { text: '"This is wrong."', good: false, why: 'Say what and why. Then suggest a fix.' }, { text: '"Who wrote this mess?"', good: false, why: 'Review the code, never the person.' }, { text: '"Question: what happens if the list is empty?"', good: true, why: 'A question invites a fix without blame.' }, { text: '"`nit:` extra space on line 12 (optional)"', good: true, why: 'It marks a tiny thing. The author can choose.' }, { text: '"Just rewrite everything."', good: false, why: 'Too vague. Point to one clear next step.' }]} />
</Card>

<Card id="predict-reply" type="predict">
A reviewer asks you to rename a function. You disagree. What is the best reply?

<Interactive name="Choice" options={[{ label: '"Good point! I chose this name to match the API. Happy to change it if you still prefer."', correct: true, why: 'Kind, gives your reason, and stays open.' }, { label: '"No."', why: 'Too short. Share your reason so you can agree together.' }, { label: 'Ignore it and merge anyway', why: 'Unanswered comments hurt trust. Always reply.' }]} />
</Card>

<Card id="check-habits" type="check">
Good teammates make work easy for others. Sort each habit.

<Interactive name="SortCards" buckets={[{ id: 'help', label: 'Helps the team' }, { id: 'slow', label: 'Slows the team' }]} items={[{ label: 'Write a clear PR description', bucket: 'help', why: 'Reviewers know what to check.' }, { label: 'Link the issue your PR closes', bucket: 'help', why: 'Everyone can follow the story.' }, { label: 'Say thanks after a review', bucket: 'help', why: 'Kindness keeps reviews friendly.' }, { label: 'Push straight to main and skip review', bucket: 'slow', why: 'Reviews catch bugs. Use a PR.' }, { label: 'Leave a review waiting for weeks', bucket: 'slow', why: 'Your teammate is stuck. Review soon, even briefly.' }, { label: "Force push over a teammate's commits", bucket: 'slow', why: 'Their work can vanish. Talk first.' }]} success="Sorted! You are the teammate everyone wants." />
</Card>

<Card id="win" type="win">
You can now send small PRs and give kind, useful reviews.
</Card>

<Card id="deeper" type="deeper">
Not ready yet? Open a draft PR (World 5). Some teams start review comments with a label, like `suggestion:` or `question:`. This style is called Conventional Comments. A `nit:` label tells the author the comment is small and optional. See "Kind, useful code review" in World 5.
</Card>
