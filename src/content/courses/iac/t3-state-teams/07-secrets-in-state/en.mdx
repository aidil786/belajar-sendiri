<Card id="hook" type="hook">
The shop safe gets a PIN from `random_password`. `tofu output` prints `pin = <sensitive>`. Is the PIN safe now?

<Interactive name="Choice" options={[{ label: 'No: the register keeps it as plain text', correct: true, why: 'sensitive hides it on screen. The state file still holds it.' }, { label: 'Yes: it is hidden', why: 'Hidden on screen only. Anyone who opens the register can read it.' }, { label: 'Yes: OpenTofu always encrypts it', why: 'Not by default. OpenTofu can encrypt the state, but only when you set it up.' }]} />
</Card>

<Card id="try-fix" type="try">
Run `tofu plan` and read the error. Then add `sensitive = true` to the output in `main.tf`, and run `tofu apply`.

<Interactive name="TofuSim" scenario="t3-secret-pin" goal={{ outputExists: ['pin'], resourceInState: ['random_password.pin'] }} hints={['Type tofu plan and read the error.', 'In the output block, under value, add: sensitive = true', 'Then tofu apply and yes.']} success="The output is marked sensitive, so the screen hides it." />

<Hint>Plain words: an output that holds a secret must say so.</Hint>
</Card>

<Card id="deeper" type="deeper">
OpenTofu 1.11 added ephemeral resources and write-only attributes. They keep a secret out of the register and the plan altogether. Terraform has them too (1.10 and 1.11). Lesson T4·7 shows how a pipeline gets secrets without files.
