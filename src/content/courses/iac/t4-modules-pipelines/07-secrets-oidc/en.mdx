<Card id="see-oidc" type="see">
**<Term id="oidc" course="cicd">OIDC</Term>** works like a visitor badge. The job proves who it is. The cloud lends it a key that expires soon. Put the steps in order.

<Interactive name="OrderList" items={['The job asks GitHub for a short-lived ID token', 'It shows the token to the cloud', 'The cloud checks: the right repo and branch?', 'The cloud lends keys that expire soon', 'tofu plan runs with those keys']} label="First step at the top" success="No key is stored anywhere. Each run gets its own, briefly." />
</Card>

<Card id="predict" type="predict">
Which permission lets the job ask GitHub for that ID token?

<Interactive name="Choice" options={[{ label: 'id-token: write', correct: true, why: 'It lets the job request an OIDC token. Add contents: read too.' }, { label: 'contents: write', why: 'That changes the repo. It has nothing to do with tokens.' }, { label: 'write-all', why: 'Far too much. Give the job only what it needs.' }]} />

```yaml
permissions:
  id-token: write
  contents: read
```
</Card>

<Card id="try-env" type="try">
The database password must never sit in a file. Pass it in an environment variable: `export TF_VAR_db_password=teh-tarik-42`. Then `tofu apply`.

<Interactive name="TofuSim" scenario="t4-secret-env" goal={{ typed: '^export TF_VAR_db_password=', resourceInState: ['local_sensitive_file.db_conf'] }} hints={['Type export TF_VAR_db_password=teh-tarik-42', 'Then tofu apply and yes. The plan shows (sensitive value).']} success="The password came from the environment, not from a file in Git." />

<Hint>`TF_VAR_name` fills `var.name`. In CI it comes from a secret.</Hint>
</Card>
