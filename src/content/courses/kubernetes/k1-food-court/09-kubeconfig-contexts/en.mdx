<Card id="see-kubeconfig" type="see">
<Interactive name="KubeReplay" scenario="k1-two-sites" commands={['kubectl config get-contexts']} label="kubectl config get-contexts lists two contexts: kind-dev with a star, and prod-like with the namespace shop." />

kubectl keeps a list of food courts in one file: your **<Term id="kubeconfig">kubeconfig</Term>**. It lives at `~/.kube/config`. Each row is one place you can talk to.
</Card>

<Card id="try-where" type="try">
Each row is a **<Term id="context">context</Term>**: a cluster, a user and a namespace. The star marks where commands go. Type `kubectl config current-context`.

<Interactive name="FoodCourtSim" scenario="k1-two-sites" goal={{ typed: 'config current-context' }} hints={['Type kubectl config current-context and press Enter.']} success="kind-dev: your practice cluster. Same as the pink bar." />

<Hint>The pink bar on top shows the same answer.</Hint>
</Card>

<Card id="predict" type="predict">
You type `kubectl delete pod tray` now. Which cluster loses a tray?

<Interactive name="Choice" options={[{ label: 'kind-dev, the one with the star', correct: true, why: 'Right. Commands go to the current context. <Card id="deeper" type="deeper">
Run one command somewhere else, without switching: `kubectl --context prod-like get pods`. A shell prompt that shows your context helps too.

Real rep (optional): on your laptop, `kubectl config get-contexts` lists every cluster you can reach. Is there one you forgot about?
