<Card id="see-init" type="see">
<Interactive name="KubeReplay" scenario="k2-sidecar" commands={['kubectl apply -f kedai.yaml', 'sleep 2', 'kubectl get pod kedai', 'sleep 10', 'kubectl get pod kedai']} label="First the pod shows Init:0/2 while the prep step runs. Ten seconds later it is Running with READY 2/2." />

An **<Term id="init-container">init container</Term>** is the prep cook. It runs first, finishes, then leaves. `Init:0/2` means 0 of 2 init containers are done. The web server waits for them.
</Card>

<Hint>Init containers run one by one, in the order the file lists them.</Hint>

<Card id="see-sidecar" type="see">
A **<Term id="sidecar">sidecar</Term>** is a helper who stays all day, like a log shipper. It sits under `initContainers`. Which of its lines makes `sweeper` stay all day?

<Interactive name="Choice" options={[{ label: '`restartPolicy: Always`', correct: true, why: 'It starts before the app and keeps running. Any name works.' }, { label: '`image: busybox:1.37`', why: 'The image says what it runs, not how long it stays.' }]} />
</Card>

<Card id="predict" type="predict">
In `noprep.yaml`, the prep cook exits with an error. What does `kubectl get pods` show?

<Interactive name="Choice" options={[{ label: '`Init:Error`, then `Init:CrashLoopBackOff`', correct: true, why: 'The prep step fails, so Kubernetes retries it and waits longer each time. web never starts.' }, { label: '`Running`', why: 'web waits until every init container has finished well.' }, { label: '`Completed`', why: 'Completed means exit code 0. This prep step exited with 1.' }]} />
</Card>

<Card id="check-error" type="check">
<Interactive name="KubeReplay" scenario="k2-sidecar" commands={['kubectl apply -f noprep.yaml', 'sleep 6', 'kubectl get pod noprep', 'kubectl logs noprep -c prep']} label="noprep shows Init:CrashLoopBackOff. The logs of the prep container say: where is the menu file." />

Real error: `Init:CrashLoopBackOff`. Plain words: the prep step keeps failing, so the tray never opens. Read its logs with `-c prep`.
</Card>

<Card id="win" type="win">

<Card id="deeper" type="deeper">
Native sidecars are stable since Kubernetes 1.33. Older guides put helpers under `containers:`. Then a Job never finishes while its helper runs. A native sidecar does not hold a Job open.

Real rep (optional): on a throwaway cluster, apply `kedai.yaml` and watch it with `kubectl get pod kedai -w`.
</Card>
