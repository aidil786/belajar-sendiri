**<Term id="init-container">Init container</Term>** (tukang persediaan) jalan dulu, siap, kemudian pergi. `Init:0/2` maksudnya 0 daripada 2 init container sudah siap. Server web tunggu mereka.
</Card>

<Card id="check-error" type="check">
<Interactive name="KubeReplay" scenario="k2-sidecar" commands={['kubectl apply -f noprep.yaml', 'sleep 6', 'kubectl get pod noprep', 'kubectl logs noprep -c prep']} label="noprep tunjuk Init:CrashLoopBackOff. Log container prep berkata: where is the menu file." />

Ralat sebenar: `Init:CrashLoopBackOff`. Maksudnya: langkah persediaan asyik gagal, jadi dulang tak pernah dibuka. Baca lognya dengan `-c prep`.
</Card>

<Card id="deeper" type="deeper">
Sidecar asli stabil sejak Kubernetes 1.33. Panduan lama letak pembantu bawah `containers:`. Akibatnya Job tak pernah tamat selagi pembantu berjalan. Sidecar asli tak tahan Job daripada tamat.

Latihan sebenar (pilihan): dalam kluster yang boleh dibuang, apply `kedai.yaml` dan perhati dengan `kubectl get pod kedai -w`.
</Card>
