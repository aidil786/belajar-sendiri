<Card id="hook" type="hook">
A ReplicaSet keeps 3 trays of nginx 1.29. The menu moves to 1.30, so you edit its template. What happens to the 3 trays already out?

<Interactive name="Choice" options={[{ label: 'Nothing. They stay on 1.29.', correct: true, why: 'A ReplicaSet only keeps the count. It never swaps trays that are already out.' }, { label: 'All 3 swap at once', why: 'It does not touch running trays at all. Only new trays get the new template.' }, { label: 'They swap one by one', why: 'That would be nice! A ReplicaSet cannot do it. A Deployment can.' }]} />
</Card>

<Card id="see-layers" type="see">
<Interactive name="KubeReplay" scenario="k2-deploy" commands={['kubectl apply -f shop.yaml', 'kubectl rollout status deployment/shop --timeout=120s', 'kubectl get deploy,rs,pods']} label="Applying shop.yaml makes the Deployment shop, one ReplicaSet and 3 pods. Their names share the start shop-." />

A **<Term id="deployment">Deployment</Term>** is the manager's standing order: "always 3 trays of this dish". It makes a ReplicaSet, which makes the pods. Three layers, one file.
</Card>

<Card id="predict" type="predict">
Someone deletes the ReplicaSet `shop-747bf9cf8`. Its 3 trays go with it. What does the Deployment do?

<Interactive name="Choice" options={[{ label: 'Makes it again, with fresh trays', correct: true, why: 'The standing order still says 3 trays. The manager rebuilds the missing layer.' }, { label: 'Nothing. The shop stays closed.', why: 'The Deployment is still there, and it still wants 3.' }, { label: 'It deletes itself too', why: 'Deletes flow down, never up. The order above stays.' }]} />

<Card id="check" type="check">
<Interactive name="KubeReplay" scenario="k2-deploy" commands={['kubectl apply -f shop.yaml', 'kubectl rollout status deployment/shop --timeout=120s', 'kubectl delete rs -l app=shop', 'kubectl rollout status deployment/shop --timeout=120s', 'kubectl get rs']} label="The ReplicaSet is deleted. The ReplicaSet came back with the same name. Its name comes from the template, so same template, same name. The trays inside are new.

<Card id="win" type="win">
You can now explain how a Deployment, its ReplicaSet and its pods fit together.
</Card>

<Card id="deeper" type="deeper">
Read a pod name from the left. `shop` is the Deployment. `747bf9cf8` comes from the template (the `pod-template-hash` label). The last part is random. To close the shop for good, delete the Deployment, not its pods.

Real rep (optional): on a throwaway cluster, run `kubectl get deploy,rs,pods --show-labels`.
</Card>
