Lunch rush. The new menu, nginx 1.30, is ready. If you close the stall to swap trays, hungry customers walk away. What do you want?

<Interactive name="Choice" options={[{ label: 'Swap a few trays at a time, stall open', correct: true, why: 'Customers always find a tray. </Card>

`kubectl set image` writes a new image into the order. A **<Term id="rolling-update" course="cicd">rolling update</Term>** starts. One new tray comes in, one old tray leaves, again and again.
</Card>

<Card id="predict" type="predict">
A teammate ships `nginx:1.299`. That tag does not exist. What happens to the 3 old trays?

<Interactive name="Choice" options={[{ label: 'They keep serving. The new tray is stuck.', correct: true, why: 'The rollout waits for the new tray to be ready. It never is, so the old trays stay.' }, { label: 'All 3 go down', why: 'With 3 trays, an old tray leaves only after a new one is ready.' }, { label: 'Kubernetes undoes it by itself', why: "It stops and waits. The undo is your job, or your pipeline's." }]} />
</Card>

<Card id="try-undo" type="try">
It happened. The new tray shows `ErrImagePull`, then `ImagePullBackOff`. Plain words: that image cannot be fetched. Undo the rollout.

<Interactive name="FoodCourtSim" scenario="k2-bad-rollout" board="shop" goal={{ deploymentImage: { name: 'shop', image: 'nginx:1.29-alpine' }, rolloutComplete: { name: 'shop', minRevision: 3 }, podsReady: { selector: 'app=shop', count: 3 } }} hints={['Type kubectl rollout undo deployment/shop', 'Then kubectl rollout status deployment/shop']} success="Back on the last good version. The stuck tray is gone." />

<Hint>`kubectl rollout undo deployment/shop` goes back one revision.</Hint>
</Card>

<Card id="win" type="win">
You can now ship a new version with no downtime, and undo a bad one.
</Card>

<Card id="deeper" type="deeper">
After `rollout undo`, kubectl prints a Warning: the cluster changed, but your file did not. Fix the file in Git too, or the next `apply` brings the bug back. By default, a rollout adds up to 25% extra trays. It takes away at most 25%.

Real rep (optional): on a throwaway cluster, set a bad image, then undo it.
</Card>
