<Card id="see-crash" type="see">
Real error: **<Term id="crashloopbackoff">CrashLoopBackOff</Term>**. Plain words: the app starts, crashes, and Kubernetes waits longer before each retry. Tap through it.

<Interactive name="TimelineTap" events={[{ when: 'Start', title: 'It crashes', text: 'The app starts, prints a line, and exits with an error.' }, { when: 'Restart', title: 'Try again', text: 'The kubelet starts it again in the same tray. It crashes again.' }, { when: 'Back-off', title: 'Wait longer', text: 'Now it waits 10 s, then 20 s, then 40 s, up to 5 minutes. STATUS says CrashLoopBackOff.' }]} />
</Card>

<Card id="try-logs" type="try">
Why does `oops` crash? Kubernetes cannot fix your app. Ask the tray: read its logs.

<Interactive name="FoodCourtSim" scenario="k2-crashloop" goal={{ typed: '^(kubectl|k) logs ' }} hints={['Type kubectl get pods to find the pod name', 'Then type kubectl logs deployment/oops']} success="The app said: oh no, no gas. That is an app problem. Fix the app, not the cluster." />

<Hint>`kubectl logs deployment/oops` shows what the app printed.</Hint>
</Card>

<Card id="see-pending" type="see">
<Interactive name="KubeReplay" scenario="k2-states" commands={['kubectl get pod big', 'kubectl get events --field-selector reason=FailedScheduling -o jsonpath={.items[0].message}']} label="big is Pending. The scheduler says: 0/3 nodes are available: 1 had a taint, 2 had too little CPU." />

Real error: **<Term id="pod-pending">Pending</Term>** with `Insufficient cpu`. Plain words: no stall has room for this tray. It asks for 64 CPUs.
</Card>

<Card id="predict-oom" type="predict">
`hungry` may use 64Mi of memory. Its app keeps eating more. What happens?

<Interactive name="Choice" options={[{ label: 'It gets killed, then restarted', correct: true, why: 'Going over the memory limit means killed. The kubelet restarts it, and it happens again.' }, { label: 'It just slows down', why: 'Slowing down happens with CPU. Memory has no slow lane.' }, { label: 'It moves to a bigger stall', why: 'Kubernetes never moves a running pod. It restarts it in place.' }]} />
</Card>

<Card id="see-oom" type="see">
<Interactive name="KubeReplay" scenario="k2-states" commands={['kubectl get pod hungry -o jsonpath={.status.containerStatuses[0].lastState.terminated.reason}', 'kubectl get pod hungry -o jsonpath={.status.containerStatuses[0].lastState.terminated.exitCode}']} label="The last run of hungry ended with reason OOMKilled and exit code 137." />

Real error: **<Term id="oomkilled">OOMKilled</Term>**, exit code 137. Plain words: it used more memory than its limit. STATUS shows it for a moment, then `CrashLoopBackOff`.
</Card>

<Card id="try-fix" type="try">
Real error: **<Term id="imagepullbackoff">ImagePullBackOff</Term>**. Plain words: the stall cannot fetch that image. Here the tag `1.299` is a typo. Ship `nginx:1.30-alpine` instead.

<Interactive name="FoodCourtSim" scenario="k2-bad-rollout" board="shop" goal={{ deploymentImage: { name: 'shop', image: 'nginx:1.30-alpine' }, rolloutComplete: { name: 'shop' }, podsReady: { selector: 'app=shop', count: 3 } }} hints={['Type kubectl get pods to see the stuck tray', 'Type kubectl set image deployment/shop web=nginx:1.30-alpine']} success="Fixed forward! Every tray runs a real image now." />

<Hint>`kubectl set image deployment/shop web=nginx:1.30-alpine` replaces the bad tag.</Hint>
</Card>

You can now read the four classic pod errors and know where to look.

<Card id="deeper" type="deeper">
`kubectl describe pod <name>` tells the whole story: Last State, Reason, Exit Code and Events at the end. A crashing app's last run is in `kubectl logs <pod> --previous`, if the kubelet still keeps it. World K5 teaches the full debug ladder.

Real rep (optional): on a throwaway cluster, run a pod with a wrong tag. Then read `describe`.
</Card>
