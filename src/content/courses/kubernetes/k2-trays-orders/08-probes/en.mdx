<Card id="try-sort" type="try">
Kubernetes asks each container up to three questions. Each question is a **probe**. Sort what each one does.

<Interactive name="SortCards" buckets={[{ id: 'live', label: 'Liveness: awake?' }, { id: 'ready', label: 'Readiness: ready to serve?' }, { id: 'start', label: 'Startup: warmed up?' }]} items={[{ label: 'Fails: the kubelet restarts the container', bucket: 'live', why: 'An app that is stuck gets a fresh start.' }, { label: 'Fails: no customers from the Service, no restart', bucket: 'ready', why: 'The tray steps back until it is ready again.' }, { label: 'Until it passes, the other two wait', bucket: 'start', why: 'A slow starter is not killed while it warms up.' }, { label: 'The app is loading a huge menu at start', bucket: 'start', why: 'Give it time first. Then liveness takes over.' }]} success="Sorted! Awake, ready, warmed up: three different questions." />
</Card>

<Card id="see-liveness" type="see">
<Interactive name="KubeReplay" scenario="k2-liveness" commands={['kubectl apply -f sleepy.yaml', 'sleep 30', 'kubectl get pod sleepy', 'kubectl get events --field-selector reason=Killing -o jsonpath={.items[0].message}']} label="sleepy asks nginx for /healthz, which does not exist. After 3 failed checks the container is restarted: RESTARTS goes up and the event says it failed its liveness probe." />

A **<Term id="liveness-probe">liveness probe</Term>** asks: awake? `sleepy` checks `/healthz`, a page nginx does not have. Three 404s in a row: the kubelet restarts the container.
</Card>

<Card id="try-startup" type="try">
A **<Term id="startup-probe">startup probe</Term>** gives a slow cook time. 30 tries, 10 seconds apart: up to 5 minutes. Liveness waits until it passes. Fix the typo.

<Interactive name="YamlDoctor" file="slow.yaml" manifest={'apiVersion: v1\nkind: Pod\nmetadata:\n  name: slow\nspec:\n  containers:\n    - name: web\n      image: nginx:1.29-alpine\n      startupProbe:\n        httpGet:\n          path: /\n          port: 80\n        periodSeconds: 10\n        failureTreshold: 30\n'} solution={'apiVersion: v1\nkind: Pod\nmetadata:\n  name: slow\nspec:\n  containers:\n    - name: web\n      image: nginx:1.29-alpine\n      startupProbe:\n        httpGet:\n          path: /\n          port: 80\n        periodSeconds: 10\n        failureThreshold: 30\n'} keep={['startupProbe:', ': 30']} hint="Read the unknown field slowly. One letter is missing." success="Fixed! The slow cook gets up to 5 minutes to warm up." />
</Card>

<Card id="check" type="check">
<Interactive name="KubeReplay" scenario="k2-liveness" commands={['kubectl apply -f shy.yaml', 'sleep 20', 'kubectl get pod shy']} label="shy fails only its readiness probe: READY 0/1, STATUS Running, RESTARTS 0." />

`shy` fails readiness only. READY 0/1, STATUS Running, RESTARTS 0. Not ready is not broken. It just gets no customers.

<Card id="win" type="win">
You can now pick the right probe: awake, ready or warmed up.
</Card>

<Card id="deeper" type="deeper">
A probe can be `httpGet`, `tcpSocket`, `exec` or `grpc`. Keep liveness about the app itself. If it checks the database, one slow database restarts every tray.

Real rep (optional): on a throwaway cluster, apply `sleepy.yaml` and run `kubectl describe pod sleepy`. Read the Events.
</Card>
