<Card id="see-classes" type="see">

<Interactive name="SortCards" buckets={[{ id: 'g', label: 'Guaranteed' }, { id: 'b', label: 'Burstable' }, { id: 'e', label: 'BestEffort' }]} items={[{ label: 'gold: request CPU dan memori sama dengan limit', bucket: 'g', why: 'Setiap container tempah tepat had maksimumnya. BestEffort.' }, { label: 'Hanya limit memori, lain tiada', bucket: 'b', why: 'Ada sebahagian nombor, tapi CPU dan memori tak semua sama. Burstable.' }]} success="Siap! Semua ditetapkan: Guaranteed. <Card id="deeper" type="deeper">
Kalau container hanya tetapkan limits, requests akan salin limits. Jadi limits CPU dan memori sahaja pun beri Guaranteed. Bila memori tak cukup, kubelet usir dulu pod yang guna lebih daripada request.

Latihan sebenar (pilihan): dalam kluster yang boleh dibuang, apply tiga pod itu dan jalankan `kubectl describe pod bronze`. Cari baris QoS Class.
</Card>
