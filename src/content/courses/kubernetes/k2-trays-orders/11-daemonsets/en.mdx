<Card id="hook" type="hook">
Every stall needs exactly one cleaner. When a new stall opens, it needs one too. Can a Deployment with `replicas: 3` promise that?

<Interactive name="Choice" options={[{ label: 'No. It counts trays, not stalls.', correct: true, why: 'It might put two cleaners on one stall and none on another.' }, { label: 'Yes, always', why: 'A Deployment only keeps the count. Where trays land is up to the scheduler.' }, { label: 'Yes, if you count the stalls by hand', why: 'Then every new stall needs you. Kubernetes has a better way.' }]} />
</Card>

<Card id="see-ds" type="see">
<Interactive name="KubeReplay" scenario="k2-daemonset" commands={['kubectl apply -f sweeper.yaml', 'kubectl rollout status daemonset/sweeper --timeout=120s', 'kubectl get pods -o wide']} label="The DaemonSet sweeper makes one pod on dev-worker and one on dev-worker2." />

A **<Term id="daemonset">DaemonSet</Term>** puts one tray on every stall. Look at the NODE column: one sweeper per worker. A new stall gets its own sweeper by itself.
</Card>

<Card id="predict" type="predict">
This cluster has 3 nodes. Why are there only 2 sweepers?

<Interactive name="Choice" options={[{ label: 'The control plane has a lock: a taint', correct: true, why: 'Ordinary trays stay away from it. A tray needs a key, a toleration, to sit there (World K5).' }, { label: 'The DaemonSet is broken', why: 'It is fine. It skipped a stall that is locked for it.' }, { label: 'The scheduler ran out of CPU', why: 'The sweepers ask for no CPU. Something else keeps them out.' }]} />
</Card>

<Card id="deeper" type="deeper">
In a kind cluster, `kube-proxy` and `kindnet` are DaemonSets in `kube-system`. They carry a toleration, so they run on the control plane too. A `nodeSelector` limits a DaemonSet to some stalls only.

Real rep (optional): on a throwaway cluster, run `kubectl get daemonsets -n kube-system`.
</Card>
