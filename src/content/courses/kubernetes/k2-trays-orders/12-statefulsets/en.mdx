<Card id="hook" type="hook">
Your database runs 3 copies. Copy 0 is the boss; the others follow it. After a crash, the boss must come back as the boss. Random names make that hard. What do you need?

<Interactive name="Choice" options={[{ label: 'Names that stay: web-0, web-1, web-2', correct: true, why: 'A fixed number tells everyone who is who, even after a restart.' }, { label: 'More copies', why: 'More copies do not tell you which one is the boss.' }, { label: 'A new random name every time', why: 'That is what a Deployment does. Fine for a shop, not for a database.' }]} />
</Card>

<Card id="see-sts" type="see">
<Interactive name="KubeReplay" scenario="k2-statefulset" commands={['kubectl apply -f web.yaml', 'kubectl rollout status statefulset/web --timeout=180s', 'kubectl get pods']} label="The StatefulSet web makes pods web-0, web-1 and web-2, one after another." />

A **<Term id="statefulset">StatefulSet</Term>** gives each tray a number that stays. The trays start in order: web-0 first, then web-1, then web-2.
</Card>

<Card id="try-order" type="try">

<Card id="predict" type="predict">
You delete `web-1`. What comes back?

<Interactive name="Choice" options={[{ label: 'A new pod, still named web-1', correct: true, why: 'The tray is new, but its number stays. Everyone still knows who it is.' }, { label: 'A pod named web-3', why: 'The StatefulSet fills the gap with the same number.' }, { label: 'Nothing comes back', why: 'The StatefulSet still wants 3, so it makes one.' }]} />
</Card>

<Card id="check-delete" type="check">
<Interactive name="KubeReplay" scenario="k2-statefulset-up" commands={['kubectl delete pod web-1', 'kubectl wait --for=condition=Ready pod/web-1 --timeout=90s', 'kubectl get pods']} label="web-1 is deleted. A new web-1 starts; its AGE is younger than web-0 and web-2." />

Look at AGE. `web-1` is brand new, but it kept its name. Same seat, new tray.
</Card>

<Card id="deeper" type="deeper">
A StatefulSet needs a headless Service for steady addresses like `web-0.web` (World K3). It can give each tray its own storage with `volumeClaimTemplates` (World K4). Running a database yourself is real work. Many teams use a managed one.

Real rep (optional): on a throwaway cluster, scale `web` down to 1. Watch which pods leave first.
</Card>
