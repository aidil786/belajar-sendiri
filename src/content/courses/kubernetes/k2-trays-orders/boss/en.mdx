<Card id="try-undo" type="try">

<Interactive name="FoodCourtSim" scenario="k2-boss-updated" board="shop" intro={['kubectl set image deployment/shop web=nginx:1.300-alpine']} goal={{ deploymentImage: { name: 'shop', image: 'nginx:1.30-alpine' }, rolloutComplete: { name: 'shop', minRevision: 4 }, podsReady: { selector: 'app=shop', count: 3 } }} hints={['Lesson 5: one rollout command goes back', 'Type kubectl rollout undo deployment/shop']} success="Rolled back. <Card id="deeper" type="deeper">
After the undo, `kubectl rollout history` lists revisions 1, 3 and 4. Revision 2 came back as 4, because undo reuses an old template. Pipelines often run `kubectl rollout status` with a `--timeout`. If it times out, they undo by themselves.
