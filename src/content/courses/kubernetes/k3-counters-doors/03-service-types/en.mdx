<Card id="try-nodeport" type="try">

<Card id="see-lb" type="see">
<Interactive name="KubeReplay" scenario="k3-types" commands={['kubectl expose deployment shop --type=LoadBalancer --port=80 --name=shop-lb', 'kubectl get service shop-lb']} label="A LoadBalancer Service called shop-lb. Its EXTERNAL-IP says pending." />

A **<Term id="loadbalancer">LoadBalancer</Term>** asks the cloud for a street address. A plain kind cluster has no cloud, so it waits: `<pending>`.
</Card>

<Card id="check-doctor" type="check">
One letter is off. Read kubectl's answer, then fix the file.

<Interactive name="YamlDoctor" file="lb.yaml" manifest={'apiVersion: v1\nkind: Service\nmetadata:\n  name: shop-lb\nspec:\n  type: Loadbalancer\n  selector:\n    app: shop\n  ports:\n    - port: 80\n'} solution={'apiVersion: v1\nkind: Service\nmetadata:\n  name: shop-lb\nspec:\n  type: LoadBalancer\n  selector:\n    app: shop\n  ports:\n    - port: 80\n'} keep={['name: shop-lb', 'app: shop']} hint="kubectl lists the four types it knows. Plain words: Kubernetes knows four types, and `Loadbalancer` is not one of them.
</Card>

<Card id="deeper" type="deeper">
On kind, LoadBalancer addresses come from the extra tool cloud-provider-kind. NodePort calls from your laptop work on Linux. On Mac and Windows, kind's nodes hide inside Docker's small VM. There is a fifth type, ExternalName: an alias for an outside DNS name.
