An **<Term id="httproute">HTTPRoute</Term>** holds the signboards. Each rule is a path, then a Service. The most specific sign wins.
</Card>

<Card id="try-routes" type="try">
`routes.yaml` adds this sign. Apply it, then ask for `/api/menu` again.

```yaml
    - matches:
        - path:
            type: PathPrefix
            value: /api
      backendRefs:
        - name: api
          port: 80
```

<Card id="deeper" type="deeper">
Rules can also match hostnames and headers. Two `backendRefs` with weights, like 90 and 10, make a canary. Filters can redirect HTTP to HTTPS. `kubectl describe httproute` shows `ResolvedRefs`: a missing Service shows `BackendNotFound`.
