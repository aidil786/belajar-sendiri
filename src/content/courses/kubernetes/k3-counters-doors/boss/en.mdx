<Card id="try-sign" type="try">
Room 1: Mei copied the /api sign from an old Ingress. It won't apply. Fix it.

<Interactive name="YamlDoctor" file="api-route.yaml" manifest={'apiVersion: gateway.networking.k8s.io/v1\nkind: HTTPRoute\nmetadata:\n  name: kedai-api\nspec:\n  parentRefs:\n    - name: entrance\n  rules:\n    - matches:\n        - path:\n            type: Prefix\n            value: /api\n      backendRefs:\n        - name: api\n          port: 80\n'} solution={'apiVersion: gateway.networking.k8s.io/v1\nkind: HTTPRoute\nmetadata:\n  name: kedai-api\nspec:\n  parentRefs:\n    - name: entrance\n  rules:\n    - matches:\n        - path:\n            type: PathPrefix\n            value: /api\n      backendRefs:\n        - name: api\n          port: 80\n'} keep={['value: /api', 'name: api']} hint="Ingress says Prefix. HTTPRoute says something longer." success="Room 1 cleared! The sign says PathPrefix now." />

<Hint>kubectl lists the path types it knows. Pick the prefix one.</Hint>
</Card>

<Card id="try-tls" type="try">
Room 4: lock the order on the way. The certificate Secret `kedai-tls` is ready. Open the HTTPS door.

<Interactive name="FoodCourtSim" scenario="k3-boss-tls" goal={{ reachable: { url: 'https://172.18.0.200/', host: 'kedai.example' } }} hints={['Type cat tls.yaml to read it.', 'Type kubectl apply -f tls.yaml', 'Check: kubectl get gateway entrance']} success="Room 4 cleared! HTTPS on port 443 for kedai.example." />

<Hint>`tls.yaml` adds the HTTPS listener to the same entrance.</Hint>

<Card id="check-renew" type="check">
Your boss asks: "Who renews that certificate in three months?"

<Interactive name="Choice" options={[{ label: 'cert-manager, by itself, before it expires', correct: true, why: 'The annotation on the Gateway tells it what to look after.' }, { label: 'You, with a calendar reminder', why: 'That is the old way. cert-manager watches the date for you.' }, { label: 'The Gateway renews its own certificate', why: 'The Gateway only uses the Secret. cert-manager fills it.' }]} />
</Card>

<Card id="try-lock" type="try">
Final room: lock the database. Only the api may call it. Two files are ready: `db-deny.yaml` and `db-lock.yaml`. Read them first.

<Interactive name="FoodCourtSim" scenario="k3-boss-lock" goal={{ unreachable: { url: 'http://db:5432', from: 'app=shop' }, reachable: { url: 'http://db:5432', from: 'app=api' } }} hints={['Type cat db-deny.yaml and cat db-lock.yaml. Which one lets the api in?', 'Type kubectl apply -f db-lock.yaml', 'Test: kubectl exec deploy/shop -- wget -qO- -T 5 http://db:5432']} success="Boss cleared! The shop times out at the database. The api gets in." />

<Hint>Locking out everyone also locks out the api. You need a guest list.</Hint>
</Card>

<Card id="check-timeout" type="check">
Last question. Why did the shop get a timeout, not an error page?

<Interactive name="Choice" options={[{ label: 'The policy drops its packets, so nobody answers', correct: true, why: 'A locked door makes no sound. The caller waits, then gives up.' }, { label: 'The database is too slow', why: 'The database answers the api at once.' }, { label: 'The Service has no endpoints', why: 'That would be Connection refused, from every pod.' }]} />
</Card>

<Card id="deeper" type="deeper">
In the practice cluster, the database answers web requests on 5432. So wget can test the lock. A real Postgres speaks its own protocol. Test it with a database client instead.
