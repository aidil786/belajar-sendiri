Bos: satu kedai, tiga dapur. Dev: 1 dulang, log `debug`. Staging: 2 dulang, `info`. Prod: 3 dulang, `warn`. Satu base, tiga nota lekat. Buka semuanya.
</Card>

<Card id="try-dev" type="try">
Dapur 1: dev. Pratonton dahulu, kemudian buka.

<Interactive name="FoodCourtSim" scenario="k4-kitchens" namespace="dev" goal={{ replicas: { name: 'shop', count: 1, namespace: 'dev' }, objectExists: ['dev/configmap/settings'], podsReady: { selector: 'app=shop', count: 1, namespace: 'dev' } }} hints={['Pratonton: kubectl kustomize overlays/dev', 'Buka: kubectl apply -k overlays/dev']} success="Dev sudah dibuka: 1 dulang, log yang banyak cakap." />

<Hint>Pratonton tak pernah ubah kluster. Kemudian `apply -k` yang ubah.</Hint>
</Card>

<Card id="try-fix" type="try">
Dapur 2 ada masalah. Rakan sepasukan tambah suis cache pada nota staging. API server menolaknya. Baiki nota itu.

<Interactive name="YamlDoctor" file="settings-patch.yaml" manifest={'apiVersion: v1\nkind: ConfigMap\nmetadata:\n  name: settings\ndata:\n  LOG_LEVEL: info\n  CACHE: true\n'} solution={'apiVersion: v1\nkind: ConfigMap\nmetadata:\n  name: settings\ndata:\n  LOG_LEVEL: info\n  CACHE: "true"\n'} keep={['LOG_LEVEL: info', 'CACHE: ']} keepHint="Kekalkan kedua-dua tetapan. Tukar cara CACHE ditulis." hint="Data ConfigMap sentiasa teks. Letak true dalam petikan." success="Sudah baik! Nota kata CACHE ialah teks true." />
</Card>

<Card id="try-staging-prod" type="try">
Pembaikan anda sudah ada dalam fail. Buka staging, kemudian prod.

<Interactive name="FoodCourtSim" scenario="k4-kitchens" namespace="prod" goal={{ objectExists: ['staging/deployment/shop', 'staging/configmap/settings', 'prod/configmap/settings'], replicas: { name: 'shop', count: 3, namespace: 'prod' }, podsReady: { selector: 'app=shop', count: 3, namespace: 'prod' } }} hints={['Taip kubectl apply -k overlays/staging', 'Kemudian: kubectl apply -k overlays/prod', 'Semak: kubectl get pods -n prod']} success="Staging dan prod sudah dibuka. Tiga dapur, satu resepi." />
</Card>

<Card id="check-level" type="check">
Base kata `LOG_LEVEL: debug`. Nota staging kata `info`. Apa dulang staging cetak untuk `printenv LOG_LEVEL`?

<Interactive name="Choice" options={[{ label: 'info', correct: true, why: 'Patch overlay duduk di atas base.' }, { label: 'debug', why: 'Hampir! Base cuma permulaan. Patch menang.' }, { label: 'debug dan info', why: 'Satu kunci, satu nilai. Patch menggantikannya.' }]} />
</Card>

<Card id="check-all" type="check">
<Interactive name="KubeReplay" scenario="k4-kitchens-up" namespace="all" commands={['kubectl get deployments -A -l app=shop', 'kubectl exec -n staging deploy/shop -- printenv CACHE']} label="get deployments untuk semua namespace tunjuk shop di dev 1/1, prod 3/3 dan staging 2/2. Tiga zon, tiga pesanan: 1, 2 dan 3 dulang. Staging baca nota yang anda baiki: `true`.
</Card>

<Card id="try-where" type="try">
Sebelum buat apa-apa pada prod, jadikan prod zon "anda di sini". Kemudian senaraikan dulangnya.

<Interactive name="FoodCourtSim" scenario="k4-kitchens-up" goal={{ namespaceIs: 'prod', lastTyped: 'get pods' }} hints={['Taip kubectl config set-context --current --namespace=prod', 'Kemudian: kubectl get pods']} success="Bar merah jambu kata prod. Setiap arahan kini mendarat di situ, jadi berhati-hati." />

<Hint>Perhatikan bar merah jambu di atas berubah.</Hint>
</Card>
