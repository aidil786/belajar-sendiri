<Card id="see-affinity" type="see">
**<Term id="node-affinity">Node affinity</Term>** ialah senarai hajat: syarat wajib (required) dan syarat pilihan (preferred). Pod fast perlu ssd. Ia suka zon front. Asingkan kedua-duanya.

<Interactive name="SortCards" buckets={[{ id: 'must', label: 'Wajib (required)' }, { id: 'nice', label: 'Pilihan (preferred)' }]} items={[{ label: 'disk In [ssd]', bucket: 'must', why: 'Tiada ssd, tiada gerai. Itu wajib.' }, { label: 'zone In [front]', bucket: 'nice', why: 'Front lebih baik, tapi tak wajib. Ia dapat weight.' }]} success="Betul: required menapis, preferred cuma beri markah." />

Dalam YAML, dua senarai itu nampak begini:

```yaml
affinity:
  nodeAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:
      nodeSelectorTerms:
        - matchExpressions:
            - { key: disk, operator: In, values: [ssd] }
    preferredDuringSchedulingIgnoredDuringExecution:
      - weight: 50
        preference:
          matchExpressions:
            - { key: zone, operator: In, values: [front] }
```
</Card>

<Card id="deeper" type="deeper">
`kubectl get nodes --show-labels` senaraikan label setiap gerai. Label terbina termasuk `kubernetes.io/hostname` dan, dalam cloud, `topology.kubernetes.io/zone`. Pod affinity letak pod dekat pod lain. Anti-affinity jauhkan mereka.

Latihan sebenar (pilihan): guna kluster kind untuk dibuang. Labelkan satu pekerja, kemudian apply pod dengan nodeSelector.
</Card>
