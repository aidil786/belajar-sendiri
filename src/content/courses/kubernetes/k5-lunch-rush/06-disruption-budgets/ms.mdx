<Card id="hook" type="hook">
Malam ini anda baiki node (gerai) dev-worker. Dua daripada tiga pod (dulang) kedai ada di situ. Kalau kedua-duanya pergi serentak, satu pod layan seluruh barisan. Macam mana nak elak?

<Interactive name="Choice" options={[{ label: 'Tetapkan peraturan: sekurang-kurangnya 2 pod kekal hidup', correct: true, why: 'Kemudian pod pergi satu demi satu, dan barisan terus bergerak.' }, { label: 'Jangan baiki gerai', why: 'Gerai perlu naik taraf dan dibaiki. Rancang untuknya.' }, { label: 'Baiki waktu makan tengah hari', why: 'Waktu paling sibuk ialah masa paling teruk untuk hilang pod.' }]} />
</Card>

<Card id="see-pdb" type="see">
<Interactive name="KubeReplay" scenario="k5-pdb" commands={['kubectl create pdb shop --selector=app=shop --min-available=2', 'kubectl get pdb shop']} label="PodDisruptionBudget shop dicipta: min available 2, allowed disruptions 1." />

Peraturan itu ialah **<Term id="pdb">PodDisruptionBudget</Term>** (PDB). `--min-available=2` kekalkan 2 pod hidup. Dengan 3 sedia, ALLOWED DISRUPTIONS ialah 1: satu boleh pergi pada satu masa.
</Card>

<Card id="try-drain" type="try">
Sekarang kosongkan gerai dev-worker. Lencana bahaya muncul: drain pindahkan pod. Lihat bajet buat satu pod tunggu gilirannya.

```bash
kubectl drain dev-worker --ignore-daemonsets
```

<Card id="win" type="win">
Kini anda boleh pastikan kedai terus melayan semasa anda kosongkan gerai.
</Card>

<Card id="deeper" type="deeper">
Guna `--max-unavailable` untuk sebut berapa yang boleh mati. Hati-hati: bajet yang benarkan 0 gangguan sekat setiap drain selama-lamanya. Selepas kerja, `kubectl uncordon dev-worker` buka gerai semula.

Latihan sebenar (pilihan): dalam kind, buat PDB. Kemudian drain satu pekerja dan baca setiap baris.
</Card>
