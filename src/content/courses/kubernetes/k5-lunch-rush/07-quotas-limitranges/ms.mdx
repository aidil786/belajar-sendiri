<Card id="see-quota" type="see">
<Interactive name="KubeReplay" scenario="k5-quota" commands={['kubectl apply -f quota.yaml', 'kubectl get resourcequota -n food']} label="Bajet food-quota dicipta dalam namespace food. Belum ada yang diguna: 0 daripada 10 pod, 0 daripada 1 CPU, 0 daripada 1Gi memori." />

<Card id="try-limits" type="try">
**<Term id="limit-range">LimitRange</Term>** tetapkan saiz pinggan lalai. Container tanpa requests dapat nombor ini. Tekan baris yang tetapkan request CPU lalai.

<Interactive name="SpotLines" lines={[{ text: 'kind: LimitRange' }, { text: 'spec:' }, { text: '  limits:' }, { text: '    - type: Container' }, { text: '      defaultRequest:' }, { text: '        cpu: 250m', target: true }, { text: '        memory: 128Mi' }, { text: '      default:' }, { text: '        cpu: 500m' }, { text: '        memory: 256Mi' }]} prompt="Tekan request CPU lalai." success="Ya: defaultRequest ialah request. default ialah limit." />
</Card>

<Card id="predict" type="predict">
Setiap pod kedai kini minta CPU 250m. Bajet zon ialah 1 CPU. Anda pesan 5 pod. Berapa yang bermula?

<Interactive name="Choice" compact options={[{ label: '4', correct: true, why: '4 × 250m = 1 CPU. Yang ke-5 akan lebih bajet.' }, { label: '5', why: 'Hampir! 5 × 250m ialah 1.25 CPU. Bajetnya 1.' }, { label: '0', why: 'Bajet hanya tolak pod yang terlebih.' }]} />
</Card>

<Card id="deeper" type="deeper">
`kubectl describe namespace food` tunjuk bajet dan apa yang diguna. Quota juga boleh kira objek, contohnya Service atau Secret. LimitRange boleh tetapkan min dan max juga. Kemudian pod yang minta terlalu banyak ditolak.

Latihan sebenar (pilihan): buat namespace dalam kind dan tambah kedua-dua fail. Kemudian pesan terlalu banyak pod.
</Card>
