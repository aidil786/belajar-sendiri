<Card id="see-logs" type="see">

**<Term id="logs">Logs</Term>** are the cook's notebook: everything the container prints. `kubectl logs kitchen` reads it. There's the clue: the oven was too cold.
</Card>

<Card id="try-tail" type="try">

<Hint>Type `kubectl logs kitchen --tail=1`.</Hint>
</Card>

<Card id="see-previous" type="see">
<Interactive name="KubeReplay" scenario="k2-crashloop" commands={['kubectl get pods', 'kubectl logs {pod:app=oops} --previous']} label="The oops pod is in CrashLoopBackOff. Its previous run printed: starting the kitchen, then oh no, no gas." />

`CrashLoopBackOff`: the tray keeps crashing, so Kubernetes waits longer between restarts. Each restart starts a clean notebook. `--previous` reads the notebook from the run that crashed.
</Card>

<Card id="predict" type="predict">

<Interactive name="Choice" options={[{ label: 'No. They left with the old pod.', correct: true, why: 'kubectl logs reads from the stall. <Card id="see-events" type="see">
<Interactive name="KubeReplay" scenario="k5-logs" commands={['kubectl get events --field-selector involvedObject.name=kitchen']} label="Four events for the kitchen pod: Scheduled to dev-worker, image already present, Created, Started." />

**<Term id="event">Events</Term>** are the manager's notice board: placed, pulled, started, and warnings. Kubernetes writes them, not your app. They fade after a short time.
</Card>

<Card id="win" type="win">
You can now read a tray's logs and the zone's events.
</Card>

<Card id="deeper" type="deeper">
`kubectl logs -f kitchen` follows new lines. `-c cook` picks one container. `--since=10m` shows only recent lines. `kubectl events --for pod/kitchen` shows one pod's events. By default the API server keeps events for one hour. To keep logs longer, send them to a log store (next lesson).
</Card>
