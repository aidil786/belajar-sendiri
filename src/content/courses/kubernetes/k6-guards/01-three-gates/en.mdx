<Card id="check-errors" type="check">
Three real errors. Each one comes from a different gate.

<Interactive name="SpotLines" lines={[{ text: 'error: You must be logged in to the server (Unauthorized)' }, { text: 'Error from server (Forbidden): secrets is forbidden: User "system:serviceaccount:default:ci-bot" cannot list resource "secrets" in API group "" in the namespace "default"', target: true }, { text: 'Error from server (Forbidden): error when creating "plain.yaml": pods "plain" is forbidden: violates PodSecurity "restricted:latest": …' }]} prompt="Tap the error from gate 2." success="Yes! cannot list: the job card says no." />

<Card id="deeper" type="deeper">
Kubernetes has no user objects. People come from certificates or a login provider (OIDC). Robots use ServiceAccounts, which are objects. Gate 3 has two halves. Mutating admission may change your object. Then validating admission checks it. Reads like `get` skip gate 3.
