Your CI bot only updates one thing: the shop Deployment. Today it holds a master key to the whole cluster. Which key should it carry?

<Card id="see-role" type="see">
<Interactive name="KubeReplay" scenario="k6-rbac-start" commands={['cat deployer.yaml', 'kubectl apply -f deployer.yaml']} picture={false} label="cat shows a Role called deployer: in the API group apps, on deployments, the verbs get, list and patch. kubectl apply creates it." />

A **<Term id="role">Role</Term>** is a job card. It lists verbs, like `patch`, on things, like `deployments`. It works in one zone only.
</Card>

<Card id="try-wire" type="try">
A card does nothing alone. A **<Term id="rolebinding">RoleBinding</Term>** pins it to a badge, in one zone. Wire the CI bot to `deployer`, in shop only.

<Card id="try-sim" type="try">
Now in the terminal. Apply the job card. Then pin it to `ci-bot` with a RoleBinding.

<Interactive name="FoodCourtSim" scenario="k6-rbac-start" picture={false} goal={{ canI: [{ verb: 'patch', resource: 'deployments', as: 'system:serviceaccount:default:ci-bot', allowed: true }, { verb: 'delete', resource: 'deployments', as: 'system:serviceaccount:default:ci-bot', allowed: false }] }} hints={['Type kubectl apply -f deployer.yaml', 'Then type kubectl create rolebinding ci-bot-deployer --role=deployer --serviceaccount=default:ci-bot']} success="The bot may patch deployments. It may not delete them." />

<Hint>`--serviceaccount` takes zone:name, like `default:ci-bot`.</Hint>

<Card id="predict" type="predict">
RBAC has no "deny" rule. The bot has two RoleBindings. One allows deleting pods. One does not. Can it delete pods?

<Interactive name="Choice" options={[{ label: 'Yes: one yes is enough', correct: true, why: 'RBAC only adds rights. To take one away, remove the binding.' }, { label: 'No: the stricter one wins', why: 'There is no stricter one. Nothing in RBAC says no.' }, { label: 'It depends on the order', why: 'Order does not matter. Any yes wins.' }]} />
</Card>

<Card id="win" type="win">
You can now give a bot a job card for one zone.
</Card>

<Card id="deeper" type="deeper">
A RoleBinding may point at a ClusterRole. Then that card works only in the binding's zone. Built-in ClusterRoles: `view`, `edit`, `admin`, `cluster-admin`. Pods get a short-lived ServiceAccount token. Set `automountServiceAccountToken: false` when the app never calls the API.
