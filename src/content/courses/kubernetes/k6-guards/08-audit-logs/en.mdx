<Card id="try-order" type="try">
Each rule in the audit policy picks a level: how much the guard writes. Put the levels from least to most.

<Interactive name="OrderList" items={['None: write nothing', 'Metadata: who, what, when', 'Request: also what was sent', 'RequestResponse: also what came back']} label="Least detail at the top" success="That's the ladder. More detail, bigger logs." />
</Card>

<Card id="try-sort" type="try">
Pick a level for each kind of request.

<Interactive name="SortCards" buckets={[{ id: 'meta', label: 'Metadata' }, { id: 'full', label: 'RequestResponse' }, { id: 'none', label: 'None' }]} items={[{ label: 'Anything about Secrets', bucket: 'meta', why: 'A body would copy the secret into the log.' }, { label: 'Changes to pods in your app zone', bucket: 'full', why: 'You want the full story of what changed.' }, { label: 'Constant health checks on /healthz', bucket: 'none', why: 'Thousands of boring lines. Skip them.' }]} success="Sorted! Who for secrets, everything for changes, nothing for noise." />
</Card>

<Card id="check" type="check">
Good logbook habit, or risky? Swipe each one.

<Interactive name="SwipeJudge" prose cards={[{ text: 'Ship audit logs off the cluster to safe storage', good: true, why: 'A thief with admin rights could edit a log on the node.' }, { text: 'Start the API server with no audit policy file', good: false, why: 'No policy file means no events at all.' }, { text: "On managed Kubernetes, switch on the provider's control plane logs", good: true, why: 'You cannot reach the API server there. <Card id="deeper" type="deeper">
The API server needs `--audit-policy-file` and `--audit-log-path`. Without a policy file, nothing is logged. Pod Security adds notes too, like `pod-security.kubernetes.io/audit-violations`. kind can turn auditing on with a little extra config. Its docs have an Auditing page.
