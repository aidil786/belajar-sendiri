<Card id="predict" type="predict">
Zon kedai kuatkuasakan restricted. Satu pod tetapkan `hostUsers: false` dan `runAsUser: 0`, serta semua kunci lain. Adakah pengawal benarkan masuk?

<Interactive name="Choice" options={[{ label: 'Ya: pengawal longgarkan semakan root', correct: true, why: 'Root di dalam tak pernah jadi root pada node, jadi runAsNonRoot dan runAsUser tak disemak.' }, { label: 'Tidak: restricted sentiasa tolak root', why: 'Bukan untuk pod user namespace. Dokumen longgarkan dua semakan itu.' }, { label: 'Hanya pada node Windows', why: 'User namespace untuk Linux sahaja.' }]} />
</Card>

<Card id="deeper" type="deeper">
Di mana cerita ini tak tepat: pengawal sebenar guna budi bicara. Pintu Kubernetes hanya ikut peraturan bertulis. RBAC langsung tiada senarai "tolak". Pintu semak permintaan, bukan apa container buat kemudian. securityContext dan kernel Linux jaga bahagian itu. Buku log hanya berguna kalau ada orang membacanya.
