<Card id="try-cla" type="try">
Kubernetes asks you to sign a **<Term id="cla">CLA</Term>** first. Your Git email must match your CLA email. Build the command that sets it.

<Interactive name="CommandBuilder" pieces={[{ text: 'git', means: 'Talk to Git' }, { text: 'config', means: 'change a setting' }, { text: '--global', means: 'for all your projects' }, { text: 'user.email', means: 'the email in your commits' }, { text: '"aina@example.com"', means: 'the same email as your CLA' }]} decoys={[{ text: 'user.name', means: 'your name, not your email' }, { text: '--local', means: 'this project only' }]} success="Matching emails. Now the CLA check can find you." />

<Hint>World 0 of the Git course set your email this way.</Hint>
</Card>

<Card id="deeper" type="deeper">
Kubernetes docs live in the kubernetes/website repo. Each docs page links to its source on GitHub. Docs make a great first step. You learn the review steps without deep code. Bulk fixes of style warnings are often not wanted. Always talk to the maintainers first.
