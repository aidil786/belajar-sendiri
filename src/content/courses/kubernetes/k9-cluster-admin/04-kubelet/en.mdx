<Card id="see-status" type="see">
<Interactive name="KubeReplay" scenario="k9-kubelet" picture={false} commands={['ssh dev-worker', 'systemctl status kubelet']} label="Inside dev-worker: systemctl status kubelet says loaded and enabled, active (running), with the kubelet's last journal lines under it." />

That service manager is **<Term id="systemd">systemd</Term>**, the machine’s power room. `systemctl status kubelet` asks it: is the supervisor on duty, and since when?
</Card>

<Card id="try-spot" type="try">
Read it like an admin. Tap two lines: “starts at boot” and “runs now”.

<Interactive name="SpotLines" prompt="Tap the 2 lines that matter most." lines={[{ text: '● kubelet.service - kubelet: The Kubernetes Node Agent' }, { text: '     Loaded: loaded (/etc/systemd/system/kubelet.service; enabled; preset: enabled)', target: true }, { text: '    Drop-In: /etc/systemd/system/kubelet.service.d' }, { text: '             └─10-kubeadm.conf, 11-kind.conf' }, { text: '     Active: active (running) since Sat 2026-10-31 00:55:03 UTC; 5min ago', target: true }, { text: '       Docs: http://kubernetes.io/docs/' }, { text: '   Main PID: 342 (kubelet)' }]} success="enabled = it starts at boot. active (running) = it works right now." />

<Hint>Look for the words enabled and running.</Hint>
</Card>

<Card id="try-restart" type="try">
After a kubelet setting changes, you restart it. Type `ssh dev-worker`, then `systemctl restart kubelet`. Then read its **<Term id="journal">journal</Term>**: `journalctl -u kubelet -n 5 --no-pager`. Careful: a restart changes the node.

<Interactive name="FoodCourtSim" scenario="k9-kubelet" goal={{ typed: '^systemctl restart kubelet(\\.service)?$', lastTyped: '^journalctl\\b.*(-u ?|--unit[= ])kubelet' }} hints={['Type ssh dev-worker', 'Then systemctl restart kubelet', 'Then journalctl -u kubelet -n 5 --no-pager']} success="The diary shows a fresh start, with a new process number in kubelet[…]." />

<Hint>A restart is a short stop and a start. The node stays Ready.</Hint>
</Card>

<Card id="try-build" type="try">
Build the command for the kubelet’s last 20 diary lines.

<Interactive name="CommandBuilder" pieces={[{ text: 'journalctl', means: 'open the machine’s diary' }, { text: '-u kubelet', means: 'only the kubelet’s pages' }, { text: '-n 20', means: 'the last 20 lines' }, { text: '--no-pager', means: 'print it all, don’t wait for keys' }]} decoys={[{ text: '-u containerd', means: 'the stove’s pages, not the supervisor’s' }, { text: '-f', means: 'keep watching for new lines until Ctrl+C' }]} success="That’s the one you will type most on the exam." />

<Hint>Start with journalctl, then the unit, then how many lines.</Hint>
</Card>

<Card id="check-sort" type="check">
Does it only look, or does it change the stall? Sort the commands.

<Interactive name="SortCards" buckets={[{ id: 'look', label: 'Only looks' }, { id: 'change', label: 'Changes the stall (careful)' }]} items={[{ label: 'systemctl status kubelet', bucket: 'look', why: 'It reads the service’s state.' }, { label: 'systemctl is-active kubelet', bucket: 'look', why: 'One word back: active or inactive.' }, { label: 'journalctl -u kubelet -n 20', bucket: 'look', why: 'It reads the diary.' }, { label: 'systemctl stop kubelet', bucket: 'change', why: 'The stall goes NotReady soon after.' }, { label: 'systemctl restart kubelet', bucket: 'change', why: 'A short stop, then a start.' }, { label: 'systemctl enable kubelet', bucket: 'change', why: 'It changes what starts at boot.' }]} success="Look first. <Hint>Status, is-active and journalctl never change anything.</Hint>

<Card id="deeper" type="deeper">
`cat /etc/systemd/system/kubelet.service` shows `Restart=always`: if the kubelet crashes, systemd starts it again. A planned `systemctl stop` stays stopped. `journalctl -u kubelet -f` follows new lines live; press Ctrl+C to leave.
