<Card id="try-pods" type="try">
Go straight to the stove with **<Term id="crictl">crictl</Term>**. Type `docker exec -it dev-worker2 bash`, then `crictl pods`.

<Interactive name="FoodCourtSim" scenario="k9-crictl" goal={{ typed: '^(ssh dev-worker2|docker exec -it dev-worker2 bash)$', lastTyped: '^crictl pods\\b' }} hints={['Type docker exec -it dev-worker2 bash', 'Then crictl pods']} success="The stove lists the oven pod, without asking the office." />

<Hint>crictl talks to containerd on this one machine. It needs no API server.</Hint>
</Card>

<Card id="try-logs" type="try">
Read the oven’s last words. Type `crictl ps -a --name oven`. Copy the CONTAINER id. Then type `crictl logs` and paste it.

<Interactive name="FoodCourtSim" scenario="k9-crictl" intro={['docker exec -it dev-worker2 bash']} goal={{ typed: '^crictl ps -a\\b', lastTyped: '^crictl logs (--tail[= ]?\\d+ )?[0-9a-f]{4,}' }} hints={['Type crictl ps -a --name oven', 'Copy the id from the first column. Then crictl logs <that id>']} success="“oven: no gas, cannot heat”: the same words kubectl logs shows, read from the stove." />

<Hint>The first few letters of the id are enough.</Hint>
</Card>

<Card id="win" type="win">
You can now see a node’s containers and logs with crictl.
</Card>

<Card id="deeper" type="deeper">
Use crictl to look. The kubelet runs the containers, so let the kubelet make the changes. `crictl images` lists what the stove has pulled. `crictl inspect <id>` shows one container in full.
