<Card id="try-node" type="try">
Room 1: bring dev-worker2 back. Look inside it first.

<Card id="predict" type="predict">
A snapshot waits in `/opt/backup.db`. It was taken before the delete. After a restore, what happens to objects made after it?

<Interactive name="Choice" options={[{ label: 'They are gone too', correct: true, why: 'etcd goes back to that moment. Anything newer is lost.' }, { label: 'They stay', why: 'A restore replaces the whole order book with the old copy.' }, { label: 'They are merged with the old ones', why: 'etcd does not merge. It goes back in time.' }]} />
</Card>

<Card id="try-plan" type="try">
Room 2: plan the restore before you touch anything.

<Interactive name="OrderList" items={['ssh dev-control-plane', 'etcdutl --write-out=table snapshot status /opt/backup.db', 'etcdutl --data-dir /var/lib/etcd-restore snapshot restore /opt/backup.db', 'Point etcd.yaml at /var/lib/etcd-restore (sed -i)', 'exit, wait about 30 s, kubectl get deployments']} label="First step at the top" success="Plan ready. Check, restore, repoint, wait, look." />
</Card>

<Card id="try-all" type="try">
Final room: both faults are back. Fix the stall, and bring the shop back from the snapshot. Danger: the restore rewrites etcd.

<Interactive name="FoodCourtSim" scenario="k9-boss" goal={{ nodeReady: { name: 'dev-worker2' }, deploymentRestored: { name: 'shop' } }} hints={['Room 1 again: ssh dev-worker2, systemctl start kubelet, exit.', 'ssh dev-control-plane, then etcdutl --data-dir /var/lib/etcd-restore snapshot restore /opt/backup.db', "sed -i 's#/var/lib/etcd$#/var/lib/etcd-restore#' /etc/kubernetes/manifests/etcd.yaml, then exit and wait"]} success="Boss cleared! The stall is Ready and the shop is back with 3 trays." />

<Hint>Two jobs, any order. A restore alone leaves one tray waiting on the quiet stall.</Hint>
</Card>

<Card id="check-next" type="check">
Tomorrow’s plan. Good idea, or needs work?

<Interactive name="SwipeJudge" prose cards={[{ text: 'Save etcd snapshots on a schedule, and copy them off the node', good: true, why: 'Fresh copies, kept away from the machine that may break.' }, { text: 'Keep the only snapshot on the control-plane node', good: false, why: 'If that node dies, the copy dies with it.' }, { text: 'Keep every YAML in Git as well', good: true, why: 'Re-applying from Git is often faster than a restore.' }, { text: 'Restore etcd for every small mistake', good: false, why: 'A restore loses newer work. <Card id="deeper" type="deeper">
Where the story breaks: our order book is one paper book. Real clusters often run 3 or 5 etcd members. Then every member is restored from the same snapshot. Also, our clock skips ahead; a real restart takes longer.
