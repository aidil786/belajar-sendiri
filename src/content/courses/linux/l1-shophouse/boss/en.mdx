<Card id="hook" type="hook">
Boss: the day cook left `~/kitchen` in a mess. Recipes on the floor, temp files everywhere, and the supplier note is lost. Dinner rush in 10 minutes. What comes first?

<Interactive name="Choice" options={[{ label: 'Look around before touching anything', correct: true, why: 'ls -a and find show the whole mess. Then you act calmly.' }, { label: 'Delete everything and start fresh', why: 'The recipes and the supplier note would be gone for good.' }, { label: 'Move everything into one folder', why: 'Then the mess just lives in a new room.' }]} />
</Card>

<Card id="try-recipes" type="try">
Job 1: look with `ls -a`. Then make a `recipes` room and move the three `.txt` recipes into it. Leave `oven.log` alone.

<Interactive name="LinuxSim" scenario="linux-l1-boss" goal={{ fileExists: ['~/kitchen/recipes/sambal.txt', '~/kitchen/recipes/rendang.txt', '~/kitchen/recipes/kuih.txt', '~/kitchen/oven.log'], fileMissing: ['~/kitchen/sambal.txt'] }} hints={['Make the room: mkdir recipes', 'One pattern moves all three: mv *.txt recipes/']} solution={['ls -a', 'mkdir recipes', 'mv *.txt recipes/']} success="Job 1 done! Three recipes on their shelf, the oven log untouched." />

<Hint>Every recipe ends in `.txt`.</Hint>
</Card>

<Card id="check-star" type="check">
Why `mv *.txt recipes/` and not `mv * recipes/`?

<Interactive name="Choice" options={[{ label: '* would grab the log, the old folder, even recipes itself', correct: true, why: '* matches every name. mv then complains it cannot move recipes into itself.' }, { label: '* is slower', why: 'Speed is the same. The trouble is what * picks.' }, { label: 'mv does not understand *', why: 'mv never sees the star. The shell swaps it for names first.' }]} />
</Card>

<Card id="try-tmp" type="try">
Job 2: three empty `.tmp` files clutter the floor. Check them first, then delete only those.

<Interactive name="LinuxSim" scenario="linux-l1-boss-2" goal={{ fileMissing: ['~/kitchen/tmp1.tmp', '~/kitchen/tmp2.tmp', '~/kitchen/tmp3.tmp'], fileExists: ['~/kitchen/oven.log', '~/kitchen/recipes/kuih.txt', '~/kitchen/old/box/supplier.md'] }} hints={['Look first: ls *.tmp', 'Same pattern, now delete: rm *.tmp']} solution={['ls *.tmp', 'rm *.tmp']} success="Job 2 done! The temp files are gone. Nothing else was touched." />

<Hint>Use the same pattern twice: once with `ls`, once with `rm`.</Hint>
</Card>

<Card id="judge-delete" type="check">
The night cook suggests these. Safe here, or risky?

<Interactive name="SwipeJudge" cards={[{ text: 'ls *.tmp, then rm *.tmp', good: true, why: 'Look, then delete with the very same pattern.' }, { text: 'rm *', good: false, why: 'It deletes oven.log too. No undo.' }, { text: 'rm -r old', good: false, why: 'old still holds the supplier note!' }, { text: 'find . -name "*.tmp"', good: true, why: 'A search changes nothing. Always safe.' }]} />
</Card>

<Card id="try-note" type="try">
Job 3: the supplier note is lost somewhere in `old`. Find it. Then save only the Pak Ali line into `todo.txt`.

<Interactive name="LinuxSim" scenario="linux-l1-boss-3" goal={{ fileContains: { '~/kitchen/todo.txt': 'Pak Ali brings chilli' }, fileNotContains: { '~/kitchen/todo.txt': 'Mak Su' } }} hints={['Find it: find . -name "*supplier*"', 'Save the line: grep "Pak Ali" old/box/supplier.md > todo.txt']} solution={['find . -name "*supplier*"', 'grep "Pak Ali" old/box/supplier.md > todo.txt']} success="Job 3 done! Pak Ali brings chilli on Friday. It is on the todo list." />

<Hint>`find` gives the path. `grep … > todo.txt` saves the line.</Hint>
</Card>
