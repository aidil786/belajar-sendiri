<Card id="try-sort" type="try">
`0.0.0.0` in `ss` means **every line**: the intercom and the street. `127.0.0.1` means the intercom only. Who can call each one?

<Interactive name="SortCards" buckets={[{ id: 'inside', label: 'Only from inside the server' }, { id: 'all', label: 'Anyone who can reach it' }]} items={[{ label: '127.0.0.1:3000', bucket: 'inside', why: 'The intercom. A good safe choice.' }]} success="Intercom only, or every line." />
</Card>

<Card id="predict" type="predict">
A database is used only by apps on this same server. Where should it listen?

<Interactive name="Choice" options={[{ label: '127.0.0.1', correct: true, why: 'Nobody outside can even knock. Safer.' }, { label: '0.0.0.0', why: 'Then every line can reach it. Only open what customers need.' }, { label: 'It does not matter', why: 'It matters a lot. Fewer open doors, fewer break-ins.' }]} />
</Card>

<Card id="check" type="check">
The fix for the order app is in its own settings, not in Linux. Good idea or not?

<Interactive name="SwipeJudge" prose cards={[{ text: 'Set the app to listen on 0.0.0.0, then check with ss -tln.', good: true, why: 'Then 0.0.0.0:3000 shows, and the street can call.' }, { text: 'Open every port so customers get through.', good: false, why: 'Open only the one port they need.' }, { text: 'Keep it on 127.0.0.1 and put nginx in front.', good: true, why: 'A front counter passes orders inside. You meet nginx in World L4.' }]} />
</Card>

<Card id="win" type="win">
You can now tell an intercom-only app from one that answers every line.
</Card>

<Card id="deeper" type="deeper">
Docker has the same idea: `-p 127.0.0.1:8080:80` keeps a container's hatch for this machine only. Many apps read a setting like `HOST=0.0.0.0` or `--bind`. A firewall may still stop callers (lesson 8).

Run it again with --bind 0.0.0.0 and look again.' }]} success="Same app, different lines." />
</Card>
