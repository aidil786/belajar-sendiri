A **firewall** is the guard at the door. `ufw` is Debian's easy guard. It keeps everyone out, except the extensions on its list.
</Card>

<Card id="try-order" type="try">
You are on the server over SSH. Turning the guard on first would lock you out! Put the steps in a safe order.

<Interactive name="OrderList" items={['sudo ufw allow OpenSSH', 'sudo ufw allow 80/tcp', 'sudo ufw enable', 'sudo ufw status verbose']} label="First step at the top" success="Let yourself in first. Then switch the guard on." />
</Card>

<Card id="see-enable" type="see">
<Interactive name="Transcript" title="kedai (over SSH)" label="ufw allow OpenSSH says Rules updated. ufw enable warns that it may disrupt ssh connections, asks y or n, then says Firewall is active and enabled on system startup."
  lines={[{ cmd: 'sudo ufw allow OpenSSH' }, { out: 'Rules updated' }, { cmd: 'sudo ufw enable' }, { out: 'Command may disrupt existing ssh connections. Proceed with operation (y|n)? y\nFirewall is active and enabled on system startup', color: 'green' }]} />

ufw asks before it starts. Answer `y` only when SSH is on the list.
</Card>

<Card id="deeper" type="deeper">
Under ufw sits nftables, the kernel's rule list (`sudo nft list ruleset`). Cloud firewalls sit outside the server: both must allow a port. Careful: ports published by Docker skip ufw's rules. The ufw outputs here came from a real Debian 13 lab.
