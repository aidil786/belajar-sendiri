<Term id="traceroute">traceroute</Term> lists every exchange on the way. Each line is a **hop**. This lab sits on one machine, so the times are tiny.
</Card>

<Card id="predict" type="predict">
Another day, the same traceroute shows this. Is the road broken at hop 2?

```
 1  gateway.kedai (10.0.0.1)  0.040 ms  0.004 ms  0.004 ms
 2  * * *
 3  kedai.example (203.0.113.10)  0.015 ms  0.007 ms  0.007 ms
```

<Interactive name="Choice" options={[{ label: 'No: hop 2 just stays quiet', correct: true, why: 'Hop 3 answered, so the call passed hop 2.' }, { label: 'Yes: the call stops at hop 2', why: 'Then hop 3 would never answer.' }, { label: 'The shop is down', why: 'The shop answered at hop 3.' }]} />
</Card>

<Card id="deeper" type="deeper">
Many servers block ping on purpose. No reply does not always mean down: test the real port with curl. `mtr` mixes ping and traceroute into one live table. Our traceroute outputs came from a real Debian 13 lab.
