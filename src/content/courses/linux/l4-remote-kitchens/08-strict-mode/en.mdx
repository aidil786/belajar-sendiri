<Card id="hook" type="hook">
Tonight, `tidy.sh` runs. But the folder `kedai/tmp` does not exist. What happens?

```bash
#!/bin/bash
# set -euo pipefail
cd "$HOME/kedai/tmp"
rm -f *.txt
echo "tidy done"
```

<Interactive name="Choice" options={[{ label: 'cd fails, and rm runs in your home folder', correct: true, why: 'Bash carries on after a failure. rm -f *.txt deletes the .txt files at home.' }, { label: 'It stops at cd', why: 'Only with set -e. Here that line is a comment.' }, { label: 'Nothing happens', why: 'rm still runs: in the wrong room.' }]} />
</Card>

<Card id="see-strict" type="see">
**Strict mode** is a strict supervisor. `set -euo pipefail` is three rules. Sort what each one stops.

<Interactive name="SortCards" buckets={[{ id: 'e', label: '-e' }, { id: 'u', label: '-u' }, { id: 'p', label: '-o pipefail' }]} items={[{ label: 'A command fails: stop now', bucket: 'e', why: '-e: exit at the first error.' }, { label: 'cd to a missing folder', bucket: 'e', why: 'cd fails, so -e stops the script.' }, { label: 'A jar with a typo in its name', bucket: 'u', why: '-u: a jar that was never filled is an error.' }, { label: 'grep fails inside grep … | sort', bucket: 'p', why: 'pipefail: a pipe fails if any part fails.' }]} success="-e: errors. -u: unknown jars. pipefail: broken pipes." />
</Card>

<Card id="try-strict" type="try">
Wake the supervisor: remove the `# ` in front of line 2 with `sed`. Then run `tidy.sh`. Your files must survive.

<Interactive name="LinuxSim" scenario="linux-l4-strict" goal={{ fileContains: { '~/tidy.sh': '^set -euo pipefail' }, scriptExitCode: { '~/tidy.sh': 1 }, fileExists: ['~/menu.txt', '~/prices.txt'] }} hints={["sed -i 's/^# set/set/' tidy.sh", 'head -n 2 tidy.sh, then ./tidy.sh', 'ls: menu.txt and prices.txt are still there.']} solution={["sed -i 's/^# set/set/' tidy.sh", './tidy.sh']} success="It stopped at cd with exit code 1. Nothing was deleted." />
</Card>

<Card id="deeper" type="deeper">
`-e` has blind spots: it ignores a failure inside an `if` test, or before `&&` and `||`. To allow one failure on purpose, write `cmd || true`. `trap` can tidy up when a script stops. Test scripts on a throwaway machine first.
