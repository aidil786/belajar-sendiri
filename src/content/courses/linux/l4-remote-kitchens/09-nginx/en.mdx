<Card id="try-page" type="try">
Write your sign into `/var/www/html/index.html`. root owns that folder, so use `sudo tee`. Then `curl localhost`.

</Card>

<Card id="see-door" type="see">
A second door, on port 8080, waits in `sites-available`. Sites in `sites-enabled` are on. Put the steps in order. Its file is below.

<Interactive name="OrderList" items={['sudo ln -s /etc/nginx/sites-available/kedai /etc/nginx/sites-enabled/', 'sudo nginx -t', 'sudo systemctl reload nginx', 'curl localhost:8080']} label="First step at the top" success="Link it, test it, reload, check." />

```nginx
server {
	listen 8080;
	root /var/www/html;
	index index.html;
}
```
</Card>

<Card id="try-door" type="try">
Now do it. Watch `ss -tln`: port 8080 opens only after the reload.

<Interactive name="LinuxSim" scenario="linux-l4-nginx" goal={{ portListening: [8080], reachable: { 'localhost:8080': 200 } }} hints={['sudo ln -s /etc/nginx/sites-available/kedai /etc/nginx/sites-enabled/', 'sudo nginx -t', 'sudo systemctl reload nginx, then curl localhost:8080']} solution={['sudo ln -s /etc/nginx/sites-available/kedai /etc/nginx/sites-enabled/', 'sudo nginx -t', 'sudo systemctl reload nginx']} success="Two doors: 80 and 8080, same shelf." />

<Card id="try-typo" type="try">
Someone added a site with a typo. `sudo nginx -t` names the file and line. Fix it, test, then reload.

<Interactive name="LinuxSim" scenario="linux-l4-nginx-typo" goal={{ portListening: [8080], serviceActive: ['nginx'] }} hints={['sudo nginx -t', 'cat /etc/nginx/sites-available/kedai: the root line has no ;', "sudo sed -i 's#root /var/www/html$#root /var/www/html;#' /etc/nginx/sites-available/kedai"]} solution={["sudo sed -i 's#root /var/www/html$#root /var/www/html;#' /etc/nginx/sites-available/kedai", 'sudo nginx -t', 'sudo systemctl reload nginx']} success="test is successful, reload done, 8080 open." />

<Hint>The error names line 4. The missing `;` is at the end of line 3.</Hint>
</Card>

You can now serve your own page with nginx and change it safely.

<Card id="deeper" type="deeper">
nginx can also pass orders to an app on the intercom: `proxy_pass http://127.0.0.1:3000;` (remember World L3). For HTTPS, Let's Encrypt's certbot gets a certificate and renews it. Open the door in ufw too: `sudo ufw allow 'Nginx Full'`.
