<Card id="try-page" type="try">
Tulis papan tanda anda dalam `/var/www/html/index.html`. root memiliki folder itu, jadi guna `sudo tee`. Kemudian `curl localhost`.

</Card>

<Card id="see-door" type="see">
Pintu kedua, di port 8080, menunggu dalam `sites-available`. Laman dalam `sites-enabled` sedang hidup. Susun langkahnya. Failnya di bawah.

<Interactive name="OrderList" items={['sudo ln -s /etc/nginx/sites-available/kedai /etc/nginx/sites-enabled/', 'sudo nginx -t', 'sudo systemctl reload nginx', 'curl localhost:8080']} label="Langkah pertama di atas" success="Pautkan, uji, reload, semak." />

```nginx
server {
	listen 8080;
	root /var/www/html;
	index index.html;
}
```
</Card>

<Card id="try-door" type="try">
Sekarang lakukannya. Tengok `ss -tln`: port 8080 hanya dibuka selepas reload.

<Interactive name="LinuxSim" scenario="linux-l4-nginx" goal={{ portListening: [8080], reachable: { 'localhost:8080': 200 } }} hints={['sudo ln -s /etc/nginx/sites-available/kedai /etc/nginx/sites-enabled/', 'sudo nginx -t', 'sudo systemctl reload nginx, kemudian curl localhost:8080']} solution={['sudo ln -s /etc/nginx/sites-available/kedai /etc/nginx/sites-enabled/', 'sudo nginx -t', 'sudo systemctl reload nginx']} success="Dua pintu: 80 dan 8080, rak yang sama." />
</Card>

<Card id="try-typo" type="try">
Seseorang tambah laman yang ada salah taip. `sudo nginx -t` namakan fail dan barisnya. Baiki, uji, kemudian reload.

<Interactive name="LinuxSim" scenario="linux-l4-nginx-typo" goal={{ portListening: [8080], serviceActive: ['nginx'] }} hints={['sudo nginx -t', 'cat /etc/nginx/sites-available/kedai: baris root tiada ;', "sudo sed -i 's#root /var/www/html$#root /var/www/html;#' /etc/nginx/sites-available/kedai"]} solution={["sudo sed -i 's#root /var/www/html$#root /var/www/html;#' /etc/nginx/sites-available/kedai", 'sudo nginx -t', 'sudo systemctl reload nginx']} success="test is successful, reload siap, 8080 terbuka." />

<Hint>Ralat itu namakan baris 4. `;` yang hilang ada di hujung baris 3.</Hint>
</Card>

<Card id="deeper" type="deeper">
nginx juga boleh hantar pesanan kepada aplikasi di interkom: `proxy_pass http://127.0.0.1:3000;` (ingat Dunia L3). Untuk HTTPS, certbot daripada Let's Encrypt dapatkan sijil dan membaharuinya. Buka pintu dalam ufw juga: `sudo ufw allow 'Nginx Full'`.
