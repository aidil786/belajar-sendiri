<Card id="hook" type="hook">
3 a.m. The pager rings: CPU at 95%. You get up and check. Every order works fine. Was it worth waking you?

<Interactive name="Choice" options={[{ label: 'No. Customers felt nothing.', correct: true, why: 'Right. A busy machine is not a problem until customers feel it.' }, { label: 'Yes. 95% is scary.', why: 'Scary, but harmless here. Sleep matters too.' }]} />
</Card>

A **<Term id="symptom-alert">symptom</Term>** is what the customer feels. A cause is one reason it might happen.
</Card>

<Card id="try-build" type="try">
The CPU is busy from 5m to 13m. Orders fail from 18m. Pick the rule that wakes someone only for the second.

<Interactive name="AlertRuleBuilder" scenario="o3-symptoms" alert="KedaiPain" exprs={[{ label: 'CPU above 90%', expr: 'kedai:cpu_busy:ratio > 0.9', why: 'The CPU was busy at 10m, but every order worked.' }, { label: 'More than 5% of orders fail', expr: 'sum(rate(http_requests_total{code=~"5.."}[5m])) / sum(rate(http_requests_total[5m])) > 0.05', threshold: 0.05 }]} fors={['0s', '2m']} labels={[{ labels: { severity: 'page' } }]} annotations={[{ annotations: { summary: '{{ $value | humanizePercentage }} of orders fail' } }]} goal={{ firingAt: ['25m'], quietAt: ['10m'], noFlap: true }} solution={{ expr: 1, for: 1 }} hints={['Which one did customers feel? Look at the graph at 25m.']} success="Quiet while the CPU sweats. A bell when orders fail." />

<Hint>The busy CPU never broke an order. The failing orders did hurt.</Hint>
</Card>

<Card id="check-swipe" type="check">
Swipe right if it should page someone. Swipe left if not.

<Interactive name="SwipeJudge" prose cards={[{ text: 'More than 5% of checkouts fail for 2 minutes', good: true, why: 'Customers are losing orders right now.' }, { text: 'CPU above 80%', good: false, why: 'Busy is not broken. Show it on a screen.' }, { text: 'p95 page time above 2 seconds for 5 minutes', good: true, why: 'Slow pages are pain customers feel.' }, { text: 'One pod restarted once', good: false, why: 'It healed. Count restarts on a dashboard instead.' }]} />
</Card>

<Card id="win" type="win">
You can now page people for customer pain, not for busy machines.
</Card>

<Card id="deeper" type="deeper">
Causes still matter. Put CPU, memory and disk on the screens, and in the runbook. Then on-call can find the reason fast. Prometheus's own advice: few alerts, each tied to pain a user feels.
</Card>
