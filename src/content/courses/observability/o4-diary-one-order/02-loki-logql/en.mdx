**<Term id="logql">LogQL</Term>** reads like a pipe. `| json` turns fields into labels. Then you can filter on them.
</Card>

<Card id="check-error" type="check">
```text
parse error : queries require at least one regexp or equality matcher that does not have an empty-compatible value. For instance, app=~".*" does not meet this requirement, but app=~".+" will
```

You asked for `{app=~".*"}`: "every diary". Loki refused. Which fix works?

<Interactive name="Choice" options={[{ label: '{app=~"kedai-.*"}', correct: true, why: 'Yes. It cannot match an empty label, so Loki knows where to look.' }, { label: '{app=~".*"} |= ""', why: 'The selector itself must narrow the diaries first.' }, { label: '{}', why: 'Empty braces pick nothing. Loki needs one real matcher.' }]} />
</Card>

<Card id="win" type="win">
You can now pick diaries by label and filter their lines with LogQL.
</Card>

<Card id="deeper" type="deeper">
LogQL can count too: `sum by (app) (count_over_time({app=~"kedai-.*"} | json | level=~"error|warn" [10m]))` counts problem lines per app. Keep labels few and fixed, like `app`. Never put `order_id` in a label: each value makes a new <Term id="log-stream">log stream</Term>.
